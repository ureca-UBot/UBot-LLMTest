# FAQ RAG 단계별 평가 데이터

통신 FAQ를 근거로 답변하는 LLM을 비교하기 위한 평가 자료입니다. 검색된 FAQ를 이미 제공한 상태에서 답변 정확도, 근거 준수, 답변 보류, 대화 처리와 반복 일관성을 확인합니다. 임베딩 검색 정확도와 API 라우팅 정확도는 별도 평가 대상입니다.

제공받은 엑셀 6개를 원본 파일명과 내용 그대로 보관했습니다. 각 파일의 결과 입력 템플릿은 실행 결과를 기록할 양식이며, 완료된 모델 평가 결과가 아닙니다.

## 1. 어떤 파일을 사용하면 되나요?

빠른 후보 선별에는 **300문항·총 380회** 구성을 먼저 사용하고, 통과 후보를 **500문항·620회**, **1,000문항·1,160회**로 확대할 수 있습니다. 모든 문항의 3회 반복 결과가 필요한 경우에는 전체 반복용 파일을 선택합니다.

아래 실행 횟수는 **모델 1개 기준**입니다. 고유 문항 수는 서로 다른 원본 ID 수이며, 반복 실행 행을 새 질문으로 세지 않습니다.

| 파일 | 고유 문항 | 반복 방식 | 모델당 실행 횟수 | 결과 입력 행 |
| --- | ---: | --- | ---: | ---: |
| [FAQ_RAG_300문항_반복40개_총380회.xlsx](FAQ_RAG_300문항_반복40개_총380회.xlsx) | 300 | 40문항은 각 3회, 나머지는 1회 | 380 | 380 |
| [FAQ_RAG_500문항_반복60개_총620회.xlsx](FAQ_RAG_500문항_반복60개_총620회.xlsx) | 500 | 60문항은 각 3회, 나머지는 1회 | 620 | 620 |
| [FAQ_RAG_1000문항_반복80개_총1160회.xlsx](FAQ_RAG_1000문항_반복80개_총1160회.xlsx) | 1,000 | 80문항은 각 3회, 나머지는 1회 | 1,160 | 1,160 |
| [FAQ_RAG_테스트_300개_3회.xlsx](FAQ_RAG_테스트_300개_3회.xlsx) | 300 | 전체 문항을 각 3회 | 900 | 900 |
| [FAQ_RAG_테스트_500개_3회.xlsx](FAQ_RAG_테스트_500개_3회.xlsx) | 500 | 전체 문항을 각 3회 | 1,500 | 1,500 |
| [FAQ_RAG_테스트_1000개.xlsx](FAQ_RAG_테스트_1000개.xlsx) | 1,000 | 기본 1회, 추가 회차는 별도로 기록 | 1,000 | 1,000 |

예를 들어 300문항 중 40개만 3회 실행하면 `300 + 40 × 2 = 380회`입니다. **380·620·1,160행의 실행 목록은 반복 행이 이미 포함되어 있으므로 각 행을 한 번씩 실행합니다.** 전체 목록을 다시 3회 실행하지 않습니다.

전체 3회 반복용 파일의 질문 시트는 300행 또는 500행입니다. 결과 입력 템플릿에만 900행 또는 1,500행이 준비되어 있으므로, 실행기는 질문마다 1·2·3회 요청을 별도로 만들어야 합니다.

## 2. 파일 간 관계와 단계별 확대

고유 문항은 `300문항 ⊂ 500문항 ⊂ 1,000문항` 관계입니다. 공통 원본 ID의 기본 19개 컬럼이 같은 것을 확인했습니다. 같은 규모의 전체 반복용 파일과 일부 반복용 파일도 기본 질문·컨텍스트·정답을 공유합니다.

일부 반복 구성에서는 앞 단계의 반복 문항도 유지합니다.

| 확대 단계 | 기존 실행 횟수 | 확대 후 총 실행 횟수 | 추가 실행 횟수 |
| --- | ---: | ---: | ---: |
| 300문항 → 500문항 | 380 | 620 | 240 |
| 500문항 → 1,000문항 | 620 | 1,160 | 540 |
| 300문항 → 1,000문항 | 380 | 1,160 | 780 |

기존 결과를 재사용하려면 모델 digest·양자화, 프롬프트, 입력 내용, 추론 설정과 평가 기준이 같아야 합니다. 지연 시간과 처리량을 비교할 때는 하드웨어 및 동시 요청 수도 맞춥니다. 설정이 다르거나 실패한 실행은 완료 결과로 재사용하지 않습니다.

## 3. 엑셀 시트 구성

6개 파일은 아래 6개 시트를 공통으로 포함합니다. 첫 번째 시트 이름은 데이터 규모와 반복 방식에 따라 달라집니다.

| 시트 | 내용 |
| --- | --- |
| `RAG 안정성 N건` 또는 `RAG 실행 목록 N건` | 실제 질문, FAQ 컨텍스트, 대화 이력, API 결과, 기대 행동과 정답 |
| `평가 가이드` | 공통 시스템 프롬프트, 평가 원칙, 반복 실행 방식 |
| `권장 지표` | 정확도·근거 준수·반복 일관성 등 지표의 정의 |
| `결과 입력 템플릿` | 모델 답변, 채점, 실행 조건, 지연 시간 등을 기록하는 양식 |
| `요약` | 유형·난이도별 문항 구성과 집계 안내 |
| `FAQ 원문` | 6개 파일에서 동일하게 사용하는 FAQ 190개 |

문항은 단일 FAQ, 유사 FAQ 구분·노이즈, 다중 FAQ 조합, 사용자 정보+FAQ, 조건·예외·경계값, 부분 정보, 유사하지만 답 없음, 무관 FAQ, 빈 컨텍스트, FAQ 충돌·시행일, 멀티턴 대화, 적대적 입력·범위 밖, API 결과 답변의 **13개 유형**으로 구성됩니다.

FAQ에는 평가용 합성 정책이 포함됩니다. 금액·요금제·조건 등을 실제 통신사 정책으로 사용하지 않습니다.

## 4. 모델 입력과 평가용 컬럼

각 파일의 `평가 가이드`에 있는 공통 시스템 프롬프트와 함께 아래 컬럼을 모델 입력으로 사용합니다.

| 구분 | 컬럼 | 사용 방법 |
| --- | --- | --- |
| 질문 | `User Question` (D열) | 사용자의 현재 질문 |
| 근거 | `제공 Context` (E열) | 답변에 사용할 FAQ 문맥 |
| 대화 | `대화 이력` (L열) | 해당 문항에 제공된 이전 대화 |
| 부가 입력 | `사용자 정보 / API 결과` (M열) | 해당 문항에 제공된 사용자 정보나 API 결과 |
| 채점 전용 | `기대 행동`, `실패 조건`, `필수 포함 사실`, `정답 예시`, `기대 응답 상태` 등 | 모델 입력에 포함하지 않고 답변을 받은 뒤 대조 |
| 실행·집계 전용 | `ID`, `원본 ID`, `실행 회차`, `반복 평가 대상`, `반복 선정 이유` | 실행 식별과 결과 묶음 구분에 사용 |

각 실행은 독립 요청으로 시작합니다. 이전 실행에서 생성한 답변을 다음 회차의 대화 이력에 추가하지 않습니다. 문항에 명시된 대화 이력은 매번 동일하게 제공합니다.

일부 반복용 파일의 `ID`는 실행 행마다 고유합니다. 예를 들어 `SF-0001`, `SF-0001-R2`, `SF-0001-R3`은 `원본 ID=SF-0001`의 1·2·3회 실행입니다. 전체 반복용 결과 입력표에서는 같은 ID가 반복되므로 `run_id + ID + 실행 회차`로 결과를 식별합니다.

## 5. 결과 기록과 집계

- 일부 반복 구성의 주 정확도·환각·포맷 지표는 `실행 회차=1`인 고유 300·500·1,000문항을 기준으로 집계합니다. 반복 문항을 세 배로 반영하지 않습니다.
- 반복 일관성은 `반복 평가 대상=Y`인 원본 ID별 3개 답변을 비교합니다. 같은 오답을 반복한 경우에는 일관성과 별개로 정확도 실패입니다.
- 일부 문항의 반복 결과만으로 전체 문항의 반복 안정성을 보장하지 않습니다. 반복 표본은 시나리오 특성을 기준으로 선정되었고, 실측 오류 빈도로 선정한 표본은 아닙니다.
- 규모가 다른 데이터셋의 전체 점수는 평가 문항 구성이 다르므로 직접 순위 비교하지 않습니다. 모델 간 비교에는 같은 데이터셋과 집계 기준을 사용합니다.
- 결과 입력표의 `run_id`, 모델 태그/digest, 양자화, temperature, think, 컨텍스트 길이, 최대 출력 토큰, seed, 프롬프트 버전, 동시 요청 수, 실행 환경을 함께 기록합니다.
- TTFT·TPS·지연 시간 등의 컬럼이 있다고 자동 측정되는 것은 아닙니다. 실행기가 실제로 수집한 값만 기록하고, 미측정 값은 구분해서 남깁니다.

## 6. 기존 테스트 스크립트와 연결

이 폴더는 평가 자료와 사용 안내를 공유하는 용도입니다. 기존 CSV나 실행 스크립트의 입력 경로를 변경하지 않습니다.

`test2` 실행 코드는 [`llm-model-test` 브랜치](https://github.com/ureca-UBot/UBot-LLMTest/tree/llm-model-test/scripts/test2)에 있으며, 실행 방법은 해당 브랜치의 [SETUP.md](https://github.com/ureca-UBot/UBot-LLMTest/blob/llm-model-test/scripts/test2/SETUP.md)를 따릅니다.

확인 기준 커밋 `e6a47d857f47ec6c2a94d239a59ea5806fff2b09`의 `prepare_test_set2.js`는 `data/raw/FAQ_RAG_300문항_반복40개_총380회 (1).xlsx`를 읽어 `data/eval_sets/test_set2/`에 CSV를 만듭니다. 그 원본과 이 폴더의 `FAQ_RAG_300문항_반복40개_총380회.xlsx`는 파일명만 다르고 SHA-256이 같습니다.

500·1,000문항 또는 전체 3회 반복 구성을 실행하려면 선택한 파일의 시트 이름, 반복 방식, ID·회차와 출력 경로를 실행기에 연결해야 합니다. 파일만 복사하거나 이름만 바꾼 뒤 같은 명령으로 자동 전환된다고 가정하지 않습니다. 진행 중인 실험의 입력은 유지하고, 다른 구성은 별도 실행 ID와 결과 경로로 기록합니다.

## 7. 원본 확인

[`manifest.json`](manifest.json)에 파일별 SHA-256, 바이트 크기, 질문 시트 이름, 고유 문항 수, 실행 행 수, 반복 대상 수와 결과 입력 행 수를 기록했습니다. 이 수치는 엑셀 내용을 직접 읽어 확인한 구성 정보이며 모델 평가 점수가 아닙니다.

엑셀을 다운로드한 뒤 다음과 같이 원본과 같은 파일인지 확인할 수 있습니다.

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\FAQ_RAG_300문항_반복40개_총380회.xlsx'
```

출처와 합성 여부는 각 파일의 `FAQ 원문` 시트에 기록된 정보를 참고합니다.
