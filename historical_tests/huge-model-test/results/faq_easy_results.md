# FAQ Easy 테스트 결과

> 상태: **✅ 실행 완료** (9개 모델 × 9케이스, `scripts/aggregate_faq_round.js easy`로 자동 생성) — `사람평가`/`사람 총평` 칸만 검토 후 직접 채우면 됩니다.
> 평가 방법론 전체는 [`README.md`](../README.md) 참고. 이 문서는 항목 1(답변 정확도)·2(RAG 충실도)·5(표현 품질)·6(명령 수행 능력)·7(성능)만 다룹니다.
> `사람 평가(의견)` 컬럼은 LLM Judge와 별개로, 각 결과를 직접 확인한 사람(운영자)의 의견을 적는 칸입니다. Judge와 의견이 다르면 사람 판단을 최종으로 합니다.
> `키워드 커버리지`·`ROUGE-L`·`숫자/고유명사 검증`은 Judge를 보완하는 **결정론적(규칙 기반) 보조 지표**입니다. 자세한 계산 방식은 README 10절 참고.
> ⚠️ **"모델별 결과"/"종합 비교" 표는 스크립트가 자동 생성합니다.** 손으로 고쳐도 다음 `aggregate_faq_round.js` 실행 때 덮어써지니, 표 내용을 바꾸려면 스크립트나 원본 데이터(`data/eval_sets/faq_easy.csv`)를 수정하세요. `사람평가`/`사람 총평` 칸은 스크립트가 항상 비워두므로 자유롭게 채워도 안전합니다.

## 개요

- 데이터: `data/eval_sets/faq_easy.csv` (10건, ID `E01`~`E10`)
- 난이도 특징: 사용자 질문이 FAQ 문구와 표현이 거의 일치하는 "직접 표현" 위주 — 핵심 키워드가 겹쳐서 정답 FAQ를 매칭하기 가장 쉬운 케이스
- 전제: 정답 FAQ(Primary GT)는 임베딩 검색이 이미 올바르게 찾아줬다고 가정하고, 그 FAQ 원문 + 사용자 질문을 LLM에 그대로 제공한 뒤 생성된 답변만 평가
- **E09는 처리 의도가 `MAP_API`라 이 문서(답변 생성 평가)에서는 제외**하고, `intent_classification_results.md`에서 의도 분류 정확도만 별도로 평가합니다.

## 채점 기준 (컬럼 설명)

각 모델 섹션은 **① 질문·정답·생성답변 (접이식 상세)** + **② 채점 결과 표(컴팩트)** 두 부분으로 나뉩니다. 원문 텍스트는 길어서 표에 넣으면 안 읽히므로, `<details>` 접이식 블록에 Test ID별로 **Q(질문) → 정답(원래 나와야 하는 FAQ 답변) → LLM답변**을 나란히 정리하고, 표에는 점수만 남겼습니다. 환각 내용도 같은 이유로 표 대신 해당 케이스의 접이식 블록 안에 "⚠️ 환각:" 줄로 표시됩니다.

| 컬럼 | 의미 | 판정 방식 |
|---|---|---|
| 답변정확도(Judge) | FAQ 핵심 정보를 빠짐없이 담았는가 | LLM Judge (1~5점) |
| 키워드커버리지% | 정답 FAQ 답변의 핵심 키워드가 생성 답변에 몇 % 포함됐는가 | 결정론적 (문자열 매칭) |
| ROUGE-L | 정답 답변과의 n-gram 중복도 | 결정론적 (계산) |
| RAG충실도(Judge) | FAQ 원문에 없는 내용을 추가하지 않았는가 (X인 경우 위 접이식 블록에 환각 내용 표시) | LLM Judge (O/X) |
| 숫자/고유명사검증 | 생성 답변의 숫자·고유명사가 제공된 FAQ 원문에 실제로 있는가 | 결정론적 (정규식 대조) |
| 표현품질 | 자연스러움·명확성·친절성(한국어 품질 포함) | LLM Judge (1~5점) |
| 포맷성공 | 지정 출력 형식을 지켰는가 | 결정론적 (스키마 검증) |
| Latency | 응답 1건당 소요 시간 | 계측 (ms) |
| TPS | 초당 생성 토큰 수 | 계측 |
| 사람평가(의견) | 사람이 직접 확인한 의견 (Judge와 별개, 최종 판단 기준) | 사람 (자유 텍스트) |
