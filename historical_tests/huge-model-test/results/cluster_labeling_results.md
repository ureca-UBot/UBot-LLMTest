# 클러스터 라벨링 테스트 결과 (항목 9)

> 상태: **미실행 (템플릿)** — 모델 실행 후 표를 채워 넣습니다.
> 평가 방법론 전체는 [`README.md`](../README.md) 참고. **그룹 나누기(클러스터링) 자체는 임베딩이 담당했다고 가정**하고, 정답 그룹을 그대로 LLM에 제공한 뒤 LLM이 각 그룹에 적절한 라벨/요약을 붙이는지만 평가합니다.
> `사람 평가(의견)` 컬럼은 LLM Judge와 별개로 사람이 직접 남기는 의견입니다. `라벨 구분력`은 Judge를 보완하는 **결정론적(문자열 유사도) 보조 지표**입니다 (README 8-1절 참고).

## 개요

- 데이터: `data/eval_sets/cluster_labeling.csv` (20건, ID `U01`~`U20`), 정답 4개 그룹으로 미리 분류되어 있음
- 입력 방식: 그룹별 질문 목록을 통째로 LLM에 제공 → LLM은 그룹당 **라벨(짧은 이름) + 한 줄 요약**을 생성
- 그룹 U10(발신자 정보 표시 / 스팸 차단), U20(부재중 통화 알림 / 음성사서함)은 애매성이 "높음"으로 표시된 경계 케이스 — 해당 그룹에 포함된 채로 제공하며, 라벨이 이 경계 항목까지 포괄하는지도 관전 포인트입니다.

## 정답 그룹

| 그룹 | 정답 클러스터명 | 포함 ID | 비고 |
|---|---|---|---|
| 1 | 통화 녹음 | U01, U02, U03, U04 | |
| 2 | 발신자 정보 표시 | U05, U06, U07, U08, U09, U10 | U10은 스팸 차단과 애매하게 겹침(애매성: 높음) |
| 3 | 데이터 선물 | U11, U12, U13, U14, U15 | |
| 4 | 부재중 통화 알림 | U16, U17, U18, U19, U20 | U20은 음성사서함과 애매하게 겹침(애매성: 높음) |

> 각 ID의 질문 원문·세부 의도·설계 목적은 `data/eval_sets/cluster_labeling.csv` 참고.

## 채점 기준 (컬럼 설명)

| 컬럼 | 의미 | 판정 방식 |
|---|---|---|
| 생성 라벨 | 모델이 해당 그룹에 붙인 이름 | LLM 출력 |
| 라벨 정확도 | 생성 라벨이 정답 클러스터명과 같은 주제를 가리키는가 | LLM Judge (O/X 또는 1~5점) |
| 라벨 환각 여부 | 요약이 그룹 내 질문과 무관한 내용을 포함하는가 | LLM Judge (O/X) |
| 라벨 구분력 | 같은 모델이 생성한 4개 라벨끼리 서로 충분히 구별되는가 (문자열 유사도가 낮을수록 좋음) | 결정론적 (Jaccard/편집거리) |
| 표현품질 | 라벨·요약 문구가 자연스럽고 관리자 보드에 쓰기 적합한가 | LLM Judge (1~5점) |
| Latency | 그룹 1건당 소요 시간 | 계측 (ms) |
| TPS | 초당 생성 토큰 수 | 계측 |
| 사람평가(의견) | 사람이 직접 확인한 의견 (Judge와 별개, 최종 판단 기준) | 사람 (자유 텍스트) |

## 관전 포인트

- 애매성이 "높음"인 경계 케이스(U10, U20)가 섞인 그룹에서, 라벨이 그 경계 항목까지 포괄하는 이름을 짓는가, 아니면 무시하고 좁은 라벨을 짓는가
- 작은 모델일수록 4개 그룹에 비슷한(구분력 낮은) 라벨을 붙이는 경향이 있는가
- 관리자 보드 노출을 고려했을 때 라벨 길이·톤이 실무에 적합한가 (너무 장황하거나 반대로 너무 축약되지 않았는지)
