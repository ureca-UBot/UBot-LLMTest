# FAQ RAG 안정성 테스트 결과 — Large (컨텍스트 10개)

> 상태: **미실행 (템플릿)** — 모델 실행 후 표를 채워 넣습니다.
> 평가 방법론 전체는 [`README.md`](../README.md) 참고. 이 문서는 **항목 2(RAG 충실도)를 심화 검증**하는 문서입니다. Easy/Medium/Hard와 달리 검색 랭킹과 완전히 무관하며(컨텍스트가 이미 고정 제공됨), 순도 100% LLM의 생성 행동만 테스트합니다.
> RAG 안정성 테스트는 **컨텍스트(후보 FAQ) 개수에 따라 Small(≤3개)/Medium(5개)/Large(10개) 3개 문서로 분리**했습니다 — 후보가 많아질수록 LLM이 얼마나 더 헷갈리는지를 비교하기 위함입니다 (README 7절 참고). 이 문서는 그중 Large 난이도이자 **가장 실전에 가까운(top-10 수준) 조건**입니다.
> `사람 평가(의견)` 컬럼은 LLM Judge와 별개로, 각 결과를 직접 확인한 사람(운영자)의 의견을 적는 칸입니다. Judge와 의견이 다르면 사람 판단을 최종으로 합니다.
> `숫자/고유명사 검증`은 Judge를 보완하는 **결정론적(규칙 기반) 보조 지표**입니다 (README 10절 참고).

## 개요

- 데이터: `data/eval_sets/rag_stability_large.csv` (21건, 7개 유형 × 3건)
- 컨텍스트 개수: 유형별 대부분 10개 (EC 유형만 0개)
- 특징: 긴 컨텍스트(최대 10개 FAQ) 속에서도 같은 판단(무관 거부/모순 감지/부분정보 인정/노이즈 필터링/다중 결합)을 유지하는지 보는 **가장 어려운 난이도**입니다. 실제 벡터 검색 top-10과 유사한 규모입니다.
- 채점의 핵심은 정답률이 아니라 **"기대 행동"을 따랐는가 / "실패 조건"에 해당하는 실수를 했는가**입니다.

## 채점 기준 (컬럼 설명)

Small/Medium과 동일한 기준입니다. 각 모델 섹션은 **① 질문·LLM답변 (접이식 상세)** + **② 채점 결과 표(컴팩트)** 두 부분으로 나뉩니다.

| 컬럼 | 의미 | 판정 방식 |
|---|---|---|
| 대응적절성 | 기대 행동을 따르고 실패 조건에 해당하는 실수를 하지 않았는가 | LLM Judge (Pass/Fail) |
| 숫자/고유명사검증 | 생성 답변의 숫자·고유명사가 제공된 컨텍스트에 실제로 있는가 | 결정론적 (정규식 대조) |
| 환각/실패내용 | Fail인 경우 구체적으로 어떤 문장이 문제인지 (접이식 블록에 표시) | LLM Judge (텍스트) |
| 표현품질 | 불확실성을 안내하는 문장도 자연스럽고 친절한가 | LLM Judge (1~5점) |
| 포맷성공 | 지정 출력 형식을 지켰는가 | 결정론적 (스키마 검증) |
| Latency | 응답 1건당 소요 시간 | 계측 (ms) |
| TPS | 초당 생성 토큰 수 | 계측 |
| 사람평가(의견) | 사람이 직접 확인한 의견 (Judge와 별개, 최종 판단 기준) | 사람 (자유 텍스트) |

- 컨텍스트가 길어지면서 Latency/TPS가 비례 이상으로 나빠지는 모델이 있는가 (입력 토큰 증가로 인한 처리 부담)
- PI(부분정보)·MC(다중조합) 유형처럼 "여러 조건 중 일부만 답해야 하는" 케이스에서 조건 누락이 늘어나는가
