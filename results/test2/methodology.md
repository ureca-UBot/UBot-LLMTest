# Test2 평가 기준과 해석 범위

## 개요

- 실행: 2026-09-17, Windows, RTX 4070 Ti 12,282 MiB, Ollama 0.34.0. 실행 상세와 파일 해시는 [보관 기록](../reports/test2/run-20260917.json)을 따른다.
- 입력은 [test_set2/cases.csv](../../data/eval_sets/test_set2/cases.csv)와 [test_set2/faq_master.csv](../../data/eval_sets/test_set2/faq_master.csv)이다. 고유 300문항, 그중 40문항을 각 3회 수행하여 모델당 380회, 9모델 총 3,420회다.
- 평가 항목은 `test2`의 1·2·3·5·6·7, 반복 일관성, 재판단 필요 여부다. 항목4 의도 분류·항목9 클러스터 라벨링은 이번 실행에서 제외되어 추가하지 않았다. 항목8 모델별 실측 리소스는 없으므로 성능 순위에 넣지 않는다.
- `test1`에서는 개요 → 테스트 케이스 → 채점 기준 → 모델별 접이식 질문·정답·답변과 점수 표 → 종합 비교 → 총평이라는 문서 형식만 참고했다. 이전 데이터·점수·Judge 척도·Small/Medium/Large 구분은 가져오지 않았다.
- 원본 응답, 자동 채점, 기존 자동 보고서는 수정하지 않았다. 새 평가 문서의 수치는 기존 건별 산출물을 집계한 것이다. 모델 생성·임베딩·NLI를 다시 실행하지 않았다.

## 검토 범위

자동 지표 집계와 원문 수록은 3,420건 전체를 대상으로 한다. AI의 직접 문맥 대조는 **13유형 × 2문항 × 9모델 = 234건**이다. 각 유형에서 입력 순서상 첫 회차1 문항과 마지막 Hard 회차1 문항을 공통 표본으로 골랐다. 확률 표본이 아니며 이 표본의 의견을 전체 정답률로 환산하지 않았다. 반복 2·3회차에는 새로운 AI 판정을 붙이지 않았다.

직접 대조 시 질문, 모든 제공 Context, 대화 이력, 사용자/API 정보, 정답 예시, 필수 사실을 읽었다. 의미상 정확성·조건/예외 누락·근거 밖 추가·기대 상태·출처·표현을 구분하여 자유 의견을 작성했다. `AI 검토 의견`은 사람 검수 완료를 뜻하지 않는다. 별도 의미 정답률이나 임의 가중 총점을 만들지 않았다.

## 채점 기준 (컬럼 설명)

개별 표의 이진 판정은 **통과/실패**, 상태·반복 일관성은 **일치/불일치**, 재판단 필요 표시는 **있음/없음**으로 표시한다. 재판단 필요 표시는 재판단 완료 여부가 아니다. 유사도·포함률·점수·시간·TPS와 집계 건수·비율은 수치로 표시한다. `N/A(스킵)`·`N/A(미채점)`은 실패나 0점과 구분한다.

| 항목 | 기준 | 집계 분모와 주의점 |
|---|---|---|
| 1. 답변 정확도 | BGE-M3 cosine ≥0.75 **그리고** 키워드 커버리지 ≥0.60. 커버리지 null이면 기존 코드상 유사도만 사용 | 건별 `pass` 사용. 주요 비교는 통과 건수/전체 고유문항이며 채점 누락 수를 별도 표기. 자동 지표 통과를 의미 정답 확정으로 해석하지 않음 |
| 2. RAG 충실도 | 비어 있지 않은 답변, 숫자·명사 규칙, 출처 숫자 검사, NLI의 결합 | ABSTAIN/CLARIFY/OUT_OF_SCOPE는 스킵. `faithful=true/실제 채점 건수`. 모델마다 분모가 다르며 미채점·스킵을 공개 |
| 3. FAQ 부재 판단 | 기대·예측 `ABSTAIN`의 TP/FP/FN/TN과 Precision/Recall/F1 | 원본 혼동행렬은 회차1만 사용. JSON 파싱 실패 등으로 parsed가 null인 행은 제외되므로 미집계 건수를 함께 표기. 파싱된 객체의 상태 누락·enum 오류는 비ABSTAIN으로 계산될 수 있음. 6종 기대 상태 일치율은 보조 진단이며 항목4 의도 분류와 다름 |
| 5. 표현 품질 | 100점에서 규칙 감점. 내부용어·질문에코·비존대 어미는 0점 | 원본 채점된 행 평균, 채점 건수 명시. test1의 1~5점 Judge와 다름 |
| 6. 명령 수행 능력 | 기존 스키마 검사 `format_pass` | 전체 고유문항. 문법상 JSON, 필수키·타입·상태 enum·비어 있지 않은 답변만 검사. 출처 ID의 진위와 의미 지시 전체를 검증하는 점수는 아님 |
| 7. 성능 | wall_ms 평균/P95, eval_count ÷ eval_duration 초로 TPS | 회차1의 기록값 사용. P95는 기존 코드와 동일한 정렬 후 floor(n×0.95) 인덱스. 모델 로딩 시간이 포함될 수 있음 |
| 반복 일관성 | 3회간 status와 추출 숫자 집합이 모두 동일 | 반복40문항. evidence_ids 일치는 별도. 의미 정답 여부·단위·숫자 간 대응관계는 검사하지 않음 |
| 재판단 필요 여부 | 기존 규칙의 needs_review | 전체380행과 고유300행을 구분. 오류율·미검토 잔여 수·정답률이 아님 |

## 자동 채점과 실제 답변이 다른 사례

1. **유사도 통과와 최종 통과는 다르다.** 기존 `*_summary.md` 첫 줄은 `similarity_pass`만 집계한다. 새 문서의 항목1 최종 통과는 `answer_accuracy.jsonl`의 `pass`를 사용한다. 이 판정은 포맷 성공·기대 상태 일치까지 결합한 종합 합격이 아니다. 포맷이 깨져도 answer 문자열이 있으면 자동 채점될 수 있다. 이를 변경된 모델 성능이나 재실험으로 해석하지 않는다.
2. **키워드가 의미보다 표기에 민감하다.** UI-0001의 EXAONE 2.4B·Qwen3 4B·8B는 새봄과 19,000원을 맞게 답했지만 커버리지 0.5로 최종 실패했다. 코드가 조사·어미와 숫자 쉼표 차이를 의미적으로 정규화하지 못한다. 반대로 Gemma3 4B의 PI-0004는 근거 없는 5GB를 포함했는데 항목1은 통과했다. [실제 비교](faq_ui_results.md), [부분 정보](faq_pi_results.md).
3. **NLI가 모든 근거를 함께 보지 않는다.** 사용자 정보·API는 숫자 규칙에는 포함되지만 NLI premise에는 FAQ 블록만 들어간다. 대화 이력도 premise에 포함되지 않는다. UI-0001의 올바른 가입 요금제 안내가 faithful=false인 사례가 있다. 다중 문서 조합·충돌 고지도 블록 하나가 전체 문장을 함의해야 한다는 검사 때문에 불리할 수 있다.
4. **낮은 faithful가 모두 환각은 아니다.** CF-0005에서 충돌을 고지한 Qwen3 4B·8B는 NLI에서 실패하고, 임의로 2GB를 선택한 Gemma3 4B는 faithful=true다. 반대로 Qwen3 0.6B는 ABSTAIN 상태에 실제 답변 5GB를 넣었지만 상태 기반 스킵을 받는다. `1-faithful 비율`을 검증된 환각률로 부르지 않는다. [충돌 사례](faq_cf_results.md).
5. **출처 배열의 형식과 진위는 별개다.** AR-0003의 EXAONE 2.4B, Gemma3 4B, Qwen3 1.7B는 본문은 맞지만 실제 제공되지 않은 ID를 인용한다. 기존 포맷 검사만으로는 걸러지지 않는다. [API 사례](faq_ar_results.md).
6. **표현 규칙과 정답 예시가 충돌한다.** 회차1 정답 예시 65건에 `제공된 FAQ`가 들어 있지만 표현 규칙은 이 문구를 실격으로 처리한다. 정답과 같은 길이의 답도 길이 비율 1.0이 허용 밴드 1.2~2.5 밖이어서 15점 감점된다. Qwen3 8B SF-0001은 정답을 그대로 답하고 85점이다. 원본 점수는 유지하되 실제 한국어 품질과 같은 뜻으로 해석하지 않는다.
7. **반복 일관성은 반복 정답률이 아니다.** 같은 틀린 상태·숫자, 같은 잘못된 응답도 일관적으로 처리될 수 있다. 상태와 숫자가 같아도 핵심 비수치 조건이 달라질 수 있다. 정답 예시와 대조하는 코드는 없다.
8. **재판단 표시가 없는 답도 검토가 필요하다.** UI-0001의 일부 올바른 답은 자동 실패지만 needs_review=false다. 자동 신호와 문맥 검토가 반드시 같은 방향이 아니므로 표시가 없는 문항도 이번 표본에 포함했다.

## 실행 조건이 허용하는 결론

이번 생성 코드는 `for` 루프 안에서 각 요청을 `await`하는 순차 실행이다. **동시 요청 처리량, 대기열 지연, TTFT, 동시 수 1·2·4에서의 모델 순위는 측정되지 않았다.** TPS는 단일 응답의 토큰 생성률이며 분당 완료 요청 수와 다르다.

요청에 `think`, temperature, seed, 컨텍스트 길이, 최대 출력 토큰을 따로 지정하지 않았다. 같은 요청 코드여도 모델별 기본 설정은 같다고 보장할 수 없다. 특히 Qwen3 4B·8B의 속도 차이를 모델 크기만으로 설명하지 않는다. 현재 시간은 이 환경·기본 설정에서 관측한 값이다. 첫 호출의 로딩 여부, 출력 토큰 수와 추론 설정을 고정한 후속 실험이 필요하다.
