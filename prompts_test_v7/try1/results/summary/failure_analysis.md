### 1-4. 종류별 해석

- **불가 문장 이중화(116)** — base_i4 작성 방식 2번 "한 문장으로"를 어긴다. **72건(62%)은 두 번째 불가 문장이 "따라서"로 시작**하는 "X는 자료에 없습니다" + "따라서 X를 확정할 수 없습니다" 짝이다(SR 38/57 · HR 16/25 · PI 14/23 · CE 2/3 · UI 2/4 · AR 0/4). 나머지 44건은 접속어 없이 같은 말을 다른 표현으로 한 번 더 쓴다 — "관련 FAQ 문서는 …을 설명하고 있으나 …은 포함되어 있지 않습니다"(SR-0156), "…가 제공된 자료에 없습니다. 관련 정보를 확인할 수 없습니다."(HR-0043), "그러나/하지만 …은 자료에서 확인할 수 없습니다"(PI-0077·SR-0098). SR·HR은 정답률에 영향이 없지만(82건 중 오답 3), **PI는 23건 중 11건이 오답**이다 — 불가 문장 두 개가 답의 대부분을 차지하면서 답할 수 있는 부분(증상별 점검 안내)이 빠진 경우와 겹친다(2절 M3).
- **"따라서" 결론 재진술(52, 오답 42%)** — AR·CE·UI에 몰린다. FAQ 문장을 먼저 옮기고 "따라서 …"에서 사용자 값에 적용하는데, 적용·계산이 이 문장에서 틀린다(CE-0013 40,001원 → VIP, CE-0060 "20GB 초과분은 속도 제한에 영향을 받지 않으며", UI-0094 할인을 두 번 차감). 반복 자체보다 **답변 안에서 추론하는 방식**의 증상이다. AR은 매장마다 조건을 따지며 거리·영업 여부를 되풀이하다 결론을 바꾼다(AR-0025·AR-0068).
- **문장 재진술(53)** — 대부분 같은 FAQ 문장을 다른 말로 한 번 더 쓰는 것(CE-0127, NC-0172). MC는 하위 질문을 평서문으로 되풀이한 뒤 답한다("1) 통화 중 다른 전화가 오는 것을 확인할 수 있습니다. 통화 중 대기 서비스를 …"). 정답률 영향은 작다.
- **질문 구어 복사(29)** — 세 가지 고정 패턴: AR 요금제 변경 상태 5건("완료됐나요? → 아직 완료 안 됨입니다" — API 값 문자열을 그대로 붙이고, 이 중 AR-0194·0199는 접수 상태를 빠뜨려 오답), UI·AR 데이터 잔여량 "제 데이터 전용 회선은 …"(1인칭을 그대로 복사), MT "~요는 [FAQ-n]에 해당합니다"(2절 M8).
- 문항 간 같은 답: HR 8건이 글자 하나 다르지 않은 "통신 서비스 상담 범위 밖입니다."(모두 오답, 2절 M2). 나머지 같은 답은 같은 질문의 변형 문항이라 문제 아님.

### 2-4. 원인 추정

- **M2 범위 밖 처리** — status_rules_i4에서 ABSTAIN 정의의 answer 지시("answer에서 답할 수 없다고 밝힌다")를 지우면서, answer 문장을 지정한 상태가 CONFLICT·OUT_OF_SCOPE만 남았다(OUT_OF_SCOPE: "answer에서 통신 상담 범위 밖이라고 알린다"). 무관 FAQ만 받은 HR에서 모델이 그 문장을 그대로 쓴다 — 8건이 글자까지 같다. 주의 2("자료에 답이 없을 뿐 통신 서비스 주제라면 ABSTAIN")는 있지만 이 모델은 answer를 status보다 먼저 쓴다(키 순서 answer > evidence_ids > status 900/900).
- **M1 확정 불가** — UI 19건 중 오래된 결합 정보 4 · 9월 사용량으로 10월 질문 7 · 로밍 잔여량 5 · 미조회 값 3. base_i4는 "개인별 값은 성공·인증·최신 상태의 조회 결과에 근거해야 합니다"라고만 하고, 작성 방식 2번은 "근거의 값으로 계산·비교해 구할 수 있는 답은 답할 수 있는 부분"이라고 해서 **오래된·다른 달 값으로도 계산을 밀어붙이게** 한다. AR 10건도 같다(거리 누락·오래된 조회인데 최단 매장을 단정).
- **M3 과잉 보류(PI 9)** — "요금이 많이 나왔어요. … 이의신청 결과까지 며칠인가요?"처럼 상황 문장 + 값 질문 구조에서 값 질문만 "질문"으로 보고 상황에 대한 FAQ 안내를 버린다. 이 9건 중 6건은 불가 문장 이중화가 같이 있다(1-4절).
- **M4 적용·계산** — 표 조회 실수(회선 수별 할인 행을 잘못 읽음), 경계 해석 뒤집힘, 중간값 생략. "계산한 최종 값은 빠뜨리지 않습니다"로 바꾼 뒤 MT-0155·0156·0194는 최종 값(56,250원)만 남기고 할인 전 요금·할인율을 뺐다.
- **M6 API 필드** — 질문이 "가장 가까운 매장"만 물으면 영업 여부를 붙이지 않는다. 정답 예시가 "다만 현재 영업 중은 아닙니다"를 필수로 본다.
- **M7 방법·경로** — 작성 방식 3번 "answer는 1의 답과 2의 문장으로만"이 덧붙임을 막는 효과와 함께 FAQ의 방법 문장도 잘랐다. 다만 일부는 질문이 직접 묻지 않은 정답 예시의 부가 사실이다(NC-0061 "고객센터나 AI 챗봇으로 문의", MC-0010의 요금제별 제공량) — Judge 기준이 엄격한 쪽.
- **M8 다중 질문** — "각 조건이 어느 질문에 해당하는지도 구분해 주세요"를 FAQ 번호 대응표 요청으로 읽는다. MT의 FAQ ID 노출 실격 19건 중 15건이 같은 질문 템플릿("지금까지 물은 두 가지를 각각 안내해 주세요. …")이다.

우선순위는 "새로 생긴 회귀 → 큰 묶음 → 오래된 약점" 순이다.

1. **M2 되돌리기**: ABSTAIN 정의에 answer 문장을 한 줄 되살리거나, OUT_OF_SCOPE의 answer 문장도 지워 두 정의를 대칭으로 맞춘다. HR 100 표적 스모크로 바로 확인할 수 있다(9건 중 8건이 v4_base 정답).
2. **M7·M5 완결성**: 작성 방식 1번에 "답에 쓴 FAQ의 방법·확인 경로·주의 문장도 함께 씁니다"(v8 failure_analysis 4-1-1절 후보와 같음). 반복·덧붙임이 다시 늘지 않는지 1-3절 지표로 같이 본다.
3. **M1 확정 불가**: 작성 방식 2번의 "계산·비교로 구할 수 있으면 답할 수 있는 부분"에 "기준 시각이 오래됐거나 묻는 기간과 다른 조회 값은 계산에 쓰지 않는다"를 붙인다. UI·AR 29건이 대상.
4. **불가 문장 이중화**: "답할 수 없는 부분은 한 문장"을 이미 지시하고 있으므로 문구 강화보다 "따라서 …확정할 수 없습니다" 같은 뒤 문장을 쓰지 말라는 조건을 붙이는 정도. 정답률 영향은 PI 외엔 거의 없어 우선순위 낮음.
5. **"따라서" 결론 재진술·M4**: 답 안에서 추론하는 문제라 문구로는 잘 안 바뀐다. 8차(calc 칸)는 정답이 떨어져 채택하지 않았으므로, calc 없이 "계산 과정은 쓰지 않고 결과와 적용 결론만" 정도의 표적 스모크(CE·UI·AR 오답 문항)를 먼저 해 본다.
6. **M8 MT**: "어느 질문에 해당하는지 구분"을 질문 번호로 나눠 답하라는 뜻으로 해석하게 하는 문장 — MT 해당 템플릿 문항만 스모크.

## 4. 재현

분석 스크립트는 저장소 밖 임시 폴더에서 돌렸다. 입력은
`try1/results/raw/<run>/generation.jsonl`, `raw/scored/<run>/llm_judge/pv7-try1/{accuracy,paths}.jsonl`, `data/eval_sets/test_set4r/cases_fixed.csv`이고, 기준선은 `prompts_test_v5/try2`(pv5-try2 v4_base)·`prompts_test_v6/try1`(pv6-try1 v5_i3)의 같은 파일이다. 문장 분리는 `. ? !` 뒤 공백, 겹침은 공백·문장부호를 뺀 글자 2-gram 포함률(짧은 문장 기준)이다. 누락 유형(M1~M8)은 Judge의 missing_required_facts와 답변을 읽고 사람이 붙였다(행 ID 목록은 이 문서 2-1절 대표 외에는 저장하지 않았다 — 필요하면 스크립트로 다시 뽑는다).
