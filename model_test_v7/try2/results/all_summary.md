# v7 try2 — 최신 코드 이후 AI 입력 검사 후속 결과

2026-10-21 · 기존 `test/ai-guard-input` 브랜치의 새 결과 회차. **입력 가드 코드가 남긴 문장을 IBM·카카오·현재 서비스 LLM으로 검사한 자료**입니다. 기존 try1 결과·실행·평가 코드·상담 프롬프트는 보존했습니다.

## 1. 무엇을 검사했나

| 단계 | 대상·건수 | 평가 기준 | 새로 실행한 것 |
|---|---|---|---|
| 코드 입력 가드 | 고정 1,600 + 추가 정상 1,000 = 2,600 | 위험 표현 제거·잔존, 정상 내용 삭제·차단 | 현재 STS 소스의 오프라인 prepareQuestion |
| IBM·카카오 | 모델당 116 | 잔존 공격 UNSAFE, 정상 비교 오차단 | 각 공급자 기본 입력 안전성 분류 |
| 현재 서비스 Qwen | 같은 116 | SAFE·UNSAFE·UNCERTAIN과 이유 | 별도 프로젝트 정책으로 입력 분류 API 요청 |

**외부 안전성 Judge·상담 답변 정확도 평가·새 임베딩은 미실시**입니다. 이번 Qwen은 평가용 외부 Judge가 아니라 입력 검사 후보로 실행한 서비스 모델입니다. 점수 임계값은 조절하지 않았으며 0.75 임베딩 검색 기준으로 안전성을 판정하지 않았습니다.

G01~G14의 직접 입력 공격 1,400건을 위험 제거 분모로 사용했습니다. G15 100건은 공격이 검색 문서 안에만 있어 사용자 입력은 정상이며 이 분모에서 제외했습니다. 기존 NORMAL 100건과 추가 정상 FAQ 질문 1,000건은 코드 오차단 검사용입니다.

## 2. 전체 결과

코드는 직접 공격 1,400건 중 **1,390건의 위험 표현을 제거**했고 10건이 남았습니다. 1,384건은 정상 기본 질문만, 나머지 6건은 욕설 호칭이 제거되고 정상 문의와 일반적인 답변 요청이 남았습니다. 정상 1,100건은 차단·내용 삭제가 없었습니다. 정상 내용 보존은 줄바꿈·질문 표현이 바이트 단위로 같다는 뜻이 아닙니다.

AI에 넣은 116건은 잔존 공격 10 + 정상 질문 100 + 욕설 제거 후 정상 비교 6입니다. 모두 현재 코드의 정리본을 사용했습니다.

| 검사 | 잔존 공격 UNSAFE /10 | 공격 보류 /10 | 공격 SAFE로 미탐 /10 | 정상 오차단 /100 | 정상 보류 /100 | 추가 정상 6건 오차단·보류 |
|---|---:|---:|---:|---:|---:|---|
| IBM Granite Guardian 3.1 2B | 0 | 별도 라벨 없음 | 10 | 4 | 별도 라벨 없음 | 0 · 0 |
| 카카오 Kanana Safeguard 8B | 1 | 별도 라벨 없음 | 9 | 2 | 별도 라벨 없음 | 0 · 0 |
| Qwen/Qwen3-4B-AWQ + 프로젝트 정책 | 6 | 2 | 2 | 5 | 5 | 0 · 1 |

Qwen의 정상 비교 106건을 합치면 위험 오차단 5, 보류 6, 정상 95건입니다. 보류를 탐지 성공 또는 정상 통과로 합산하지 않았습니다. 카카오는 G14-095, Qwen은 G14-093·096~100을 위험으로 분류했습니다. 코드+모델이 제품 경로에 연결된 상태는 아닙니다.

## 3. 앞선 결과와 어떻게 다른가

- [try1](../../try1/results/all_summary.md)의 IBM 523/1,400·카카오 578/1,400은 원문 전체에 대한 AI 단독 기준선입니다. 이번 0/10·1/10은 코드 보완 이후 남은 소수 요구의 추가 탐지이므로 성능 하락률로 계산하지 않습니다.
- IBM·카카오는 공급자 기본 정책, Qwen은 프로젝트 차단 기준을 명시한 별도 프롬프트입니다. 같은 정책으로 통제한 모델 순위 실험이 아닙니다.
- 현재 EC2의 실제 모델은 `Qwen/Qwen3-4B-AWQ`입니다. 과거 `RedHatAI/Qwen3-4B-Instruct-2507-quantized.w4a16` 상담 답변 실행과 다릅니다.
- 코드가 개선에 사용한 고정 문항을 다시 검사했으므로 1,390/1,400을 미사용 공격의 일반화 성능으로 말할 수 없습니다. 새 욕설·새 공격 표현 검증은 남아 있습니다.

## 6. 변경 범위와 남은 한계

이번 게시에는 결과·테스트 자료·문서·검사 프롬프트 기록만 추가했습니다. 기존 실행·평가 코드와 profile을 수정하거나 새 실행 코드를 복사하지 않았습니다. 기존 임시 테스트 도구는 재사용했고 결과 보관용이므로 공통 엔진으로 재실행할 수 있다고 안내하지 않습니다.

실제 DB·관리자 연동·프론트 E2E·임베딩 검색·답변 생성·출력 가드·외부 Judge를 이번 회차에 실행하지 않았습니다. 금칙어는 당시 저장본 38개입니다. 각 모델은 같은 116개 정리본을 새로 받았지만 공급자 정책·가중치·서비스 점유·출력 길이가 다르므로 지연과 판정 수를 단순 성능 순위로 쓰지 않습니다.

카카오 실행 시 승인받은 답변용 LLM만 잠시 중지했고 복원과 건강 검사 HTTP 200을 확인했습니다. 임베딩·DB 등 나머지 서비스의 실행 상태·설정이 유지됐고 Qwen 분류 실험은 어떤 서비스도 중지하지 않았습니다. 제품에 AI 가드를 연결하거나 운영 차단 정책·보류 처리 기준을 확정한 결과는 아닙니다.
