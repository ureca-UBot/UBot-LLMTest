# 방법·비교 범위·남은 한계

이번 try6는 **코드 출력 가드를 거치기 전 저장 답변을 LLM 가드에 직접 넣는 교체 비교**입니다. try5는 코드 가드가 이미 정리한 답변을 LLM 가드에 넣었습니다. 같은 v2 프롬프트를 쓰지만 입력 답변이 다르므로 try5의15건 탐지9와 이번 실제 문제 지적8을 단순 성능 증감으로 해석하지 않습니다.

## 입력과 근거

- 이전 실제 채팅510건 중 답변 생성448건만 사용했습니다. 하드400건과 이전110건의 각 질문은 독립적인 첫 턴입니다. 멀티턴 가능한 제품 흐름을 통과했지만 이어지는 실제 다회차 대화 시험은 아닙니다.
- 62건은 답변 생성 전 종료했습니다. FAQ 검색 부족56, 질문 수 제한3, 입력 가드2, 임베딩 오류1입니다.
- 기존 JSON 파서가 추출하고 코드 출력 가드에 넘기기 직전의 `output_guard.before` 본문을 사용했습니다. 417건은 JSON에서 추출한 answer 문자열과 기존 캡처가 일치했고, 비정형31건은 기존 파서의 실제 캡처를 유지했습니다. 원시 JSON 봉투 전체를 일반 답변으로 오인해 내부 필드 노출로 분류하지 않았습니다.
- 가드 질문에는 실제 답변 모델에 전달된 정리본을 사용했습니다. 원본 질문은 감사용이며 앞에서 제거된 공격 문장을 되살려 보내지 않았습니다.
- FAQ는 실제 답변 생성 프롬프트에 포함됐던 번호와 원문을 대조했습니다. 검색 후보 전체나 외부 상식을 공식 근거로 추가하지 않았습니다. 같은 FAQ 번호의 서로 다른 실제 발췌문도 임의로 합치지 않았습니다.
- 107건에서 매장 도구 콜백이 제공됐으나 저장 래퍼에 내부 도구 실행 결과는 없습니다. 매장 지도도 저장되지 않았습니다. 이 기록만으로 실제 매장 조회 성공을 증명하거나 로그가 없다는 이유로 실행이 없었다고 단정하지 않습니다.

## 요청과 검증

- 모델: RedHatAI/Qwen3-4B-Instruct-2507-quantized.w4a16. v2 프롬프트는 try5 게시본과 바이트 동일합니다.
- temperature0, max_tokens1800, 동시성1, response_format=json_object, 자동 재시도0. 같은448건을 한 번씩 요청했습니다.
- 질문 계획·답변 생성·임베딩·DB·외부 Judge 재호출은 모두0회입니다. 신규 호출은 저장 답변을 검사하는 LLM 가드448회뿐입니다.
- 원시 ALLOW382/BLOCK61/REVIEW5와 기존 검증 후 ALLOW237/BLOCK52/INVALID155/REVIEW4를 분리합니다. INVALID는 explanation 누락152건과 정확한 문제 인용 실패3건입니다.
- 기존 v2 검증기의 필수 최상위 필드·자료형·정확한 BLOCK 구절 기준을 재사용했습니다. checks의 모든 enum·FAQ 인용 사실성까지 강제한 JSON schema 검증은 아닙니다. 별도 사유 코드 경고1건도 보존했습니다.
- 후보 답변과 근거를 이 대화에서 대조한23건 중22건의 검토는 개발 사례 점검입니다. 전체448건의 답변 안전성 정답을 독립적으로 전수 채점하지 않았습니다. 입력 ATTACK/NORMAL을 답변 정답으로 사용하거나 일반 정확도·오차단률을 주장하지 않습니다.
- 실험 프롬프트에는 내부 지시/비밀 노출, 조작 수용, 허위 실행, 근거 없는 서비스 사실, 명확한 욕설·모욕·차별 등을 포함했습니다. 공격적인 질문에 안전하게 거절한 답변은 허용합니다. 단어가 한 번 나오면 무조건 차단하는 금칙어 일치 정책은 아닙니다.

## 제품 동작과의 차이

- 기존 코드의 정리116건에는 문제 문장 삭제뿐 아니라 출처/번호/표기 정리 및 정상 문장 오삭제가 섞여 있습니다. 116건의 공격 차단 성공이 아닙니다.
- 코드 가드는 문장별 삭제가 가능하지만 이번 LLM 가드는 답변 전체 ALLOW/BLOCK입니다. ALLOW는 검사 전 답변을 그대로 반환하고 BLOCK은 고정 안내를 가정한 오프라인 시뮬레이션입니다. REVIEW/INVALID에 대한 제품 표시·재시도 정책은 이번에 정하지 않았습니다.
- 코드의 FAQ 부족 후보 선별·미응답 저장·관리자 검토 연결을 LLM으로 대체하거나 제품에 붙인 시험이 아닙니다.
- 속도는 공유 GPU의 이번 요청 측정입니다. 이전 입력 분류와 답변 생성은 모델/서빙/출력 계약이 다를 수 있으므로 순수한 프롬프트 길이 효과나 운영 지연 보장으로 해석하지 않습니다.
- 기존 서비스7개는 상태·컨테이너 ID·시작 시각이 동일했고 답변 API HTTP200을 확인했습니다. 이번 임시 모델과 전용 접속창만 정리했습니다.
