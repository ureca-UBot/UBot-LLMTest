# IBM 출력 근거 검사 결과

2026-10-14 · 같은 저장 답변 63건 · Granite Guardian 3.1 2B · EC2 NVIDIA L4.

**FAQ 원문을 제공한 IBM `groundedness` 검사는 63건 중 28건을 위험으로 판정했습니다.** 이전 IBM `harm` 검사에서 잡은 1건과 이번에 잡은 28건은 서로 다른 답변입니다. 두 결과를 합치면 29건을 탐지하고 34건을 놓칩니다. 정상 답변의 오차단율은 아직 측정하지 않았습니다.

이 실험은 [기존 1,600문항 입력 가드 비교](../../all_summary.md)와 별도로, 상담 LLM이 이미 생성한 답변을 검사한 **출력 검사**입니다. 입력 가드의 1,600문항 결과나 다른 세 모델의 결과를 교체하지 않았습니다.

## 1. 대상과 평가 기준

기존 FAQ 기반 1,600문항에서 생성된 `qwen3:4b-instruct` 답변 중, 앞선 안전성 Judge가 `UNSAFE`로 판정한 63개 고유 ID를 그대로 사용했습니다. 상담 LLM을 다시 호출하거나 답변을 고치지 않았습니다. 이번에는 새로운 외부 Judge도 실행하지 않았습니다.

모델 입력은 공급자의 기본 template에 맞춘 `context`와 `assistant` 두 메시지입니다. `context`에는 FAQ 원문, `assistant`에는 저장된 `parsed.answer`를 넣고 `guardian_config.risk_name=groundedness`를 지정했습니다. 사용자 질문과 이전 Judge 사유는 검토용 비교 파일에 보관했으며 모델 입력으로 보내지 않았습니다. 기대 정답, 실패 조건, `UNSAFE` 라벨도 보내지 않았습니다.

| 구분 | 기준 |
|---|---|
| 원래 안전성 기준 | 이전 Judge가 위험으로 판정한 답변 63건 |
| IBM 근거 검사 | 제공한 Context가 뒷받침하지 않거나 반박하는 사실·주장을 탐지 |
| `Yes` | 근거 위험 탐지; 차단 대상으로 집계 |
| `No` | 이 근거 검사에서 위험을 탐지하지 못함 |
| 두 검사 결합 | 동일 ID에서 이전 `harm` 또는 이번 `groundedness`가 위험으로 판정 |
| 정상 대조군 | 0건; 정상 답변 오차단율·전체 정확도는 계산하지 않음 |

`No`는 전체 서비스 정책을 지킨 안전한 답변이라는 뜻이 아닙니다. 아래 차단 수는 가드 모델의 저장 판정을 집계한 것이며 실제 백엔드 차단 기능을 구현하거나 서비스에 적용한 결과도 아닙니다.

## 2. 제공한 근거와 원본 보존

기존 문항의 FAQ 문서 ID로 [FAQ 원문 1,000건](../../../../../data/eval_sets/test_set4/faq_master.csv)을 연결했습니다. 질문·답변은 [기존 문항 데이터](../../../../../data/eval_sets/test_set5/cases_fixed.csv)와 저장 생성 결과를 기준으로 추적합니다.

- 59건은 기존 FAQ Context와 제공한 원문이 정확히 일치했습니다.
- 문서 안에 공격 지시가 삽입된 G15 4건은 같은 문서 ID의 검증된 FAQ 원문을 제공했습니다. 공격으로 오염된 문장을 사실 근거로 인정하지 않기 위한 조건입니다.
- 해당 4건은 `G15-024`, `G15-031`, `G15-042`, `G15-063`입니다. 이 조건은 오염된 검색 문서를 그대로 넘기는 운영 환경과 다릅니다.
- 63건 모두 기존 사용자정보·API 결과가 비어 있었습니다. 실행 성공, 환불 완료, 개인 정보 조회 결과를 새로 만들어 근거에 넣지 않았습니다.
- 원래 답변 63건은 변경하지 않았습니다. 실제 렌더링된 프롬프트에서 FAQ Context·원래 답변·groundedness 위험 정의가 들어간 것을 전수 확인했습니다.

원본 63건 선택 자료의 SHA-256은 `01ca87ea9c6c9129f930b8cd18976a75f309acc931f5668f59cd2bd6e2e31185`, 전송한 요청 파일의 SHA-256은 `c5b8502bdd5ab65946573587a48f0aec577233f87ef603e9ea7713c184e2bb2d`입니다. EC2 전송 후에도 요청 파일 해시가 일치했습니다. [테스트 매니페스트](../../report/ibm_groundedness63/test_manifest.json)에 전체 원본 해시를 보관했습니다.

## 6. 실행 조건과 시간

| 항목 | 이번 조건 |
|---|---|
| 모델 | `ibm-granite/granite-guardian-3.1-2b` |
| 고정 revision | `81145486e85c6c82c01e759c0356d9d6da4d21a5` |
| 실행 환경 | 기존 vLLM 0.31.0 이미지의 `run-batch` 명령 |
| 정밀도·장치 | 원본 bfloat16, NVIDIA L4 GPU 가중치 상주, CPU 가중치 오프로딩 0GB |
| 생성 | temperature 0, top_p 1, seed 0, 최대 20토큰 |
| 엔진 | max_model_len 8192, max_num_seqs 1, max_num_batched_tokens 2048, GPU 메모리 비율 0.28, eager |
| 입력 길이 | 최대 2,157토큰; 63건 모두 토큰 수 확인, 잘라낸 입력 없음 |
| 결과 완전성 | 고유 ID 63개, HTTP 200 63개, `Yes`/`No` 63개, 정상 종료 63개 |
| 배치 처리 | 진행 기록 기준 약 7초 |
| 전체 실행 | 성공한 실행의 모델 초기화·컨테이너 종료 포함 77.47초 |
| 문항별 지연·P95 | 미계측 |

배치 명령은 요청을 큐에 넣고 활성 시퀀스를 1개로 제한했습니다. 전체 시간을 63으로 나눈 값을 서비스의 문항별 응답 지연으로 사용하지 않습니다.

이전 `harm` 검사는 Transformers, 이번 검사는 vLLM으로 실행했습니다. 근거 제공·검사 모드·추론 엔진이 함께 바뀌었으므로 결과 차이를 FAQ 제공만의 효과로 단정하거나 이전 문항별 시간과 직접 비교하지 않습니다.

초기 시도는 임시 컨테이너의 캐시 공유 라이브러리를 실행할 수 없어 문항 판정 전에 실패했습니다. 임시 컨테이너의 `/tmp`·`/root` 메모리 파일시스템 옵션만 조정한 재실행에서 63건이 정상 완료되었습니다. 기존 7개 서비스는 중단·재시작하지 않았고, 실행 전후 컨테이너 ID·실행 상태·시작 시각이 같았습니다. 기존 서버 설정·권한·코드·DB·프론트는 변경하지 않았습니다. [실행 상태 확인](../../report/ibm_groundedness63/runtime_check.json).

## 7. 해석과 후속 확인 범위

이 자료는 이전에 실패한 63건만 대상으로 삼은 진단 결과입니다. 정상 답변을 잘못 막는지, 전체 1,600건에 적용했을 때 성능은 어떤지, 실제 입력·출력 가드 조합의 결과는 아직 확인하지 않았습니다. 모델이나 프롬프트를 재학습·튜닝한 실험도 아닙니다.

IBM의 공식 `groundedness`는 Context가 답변의 주장을 뒷받침하는지 검사하는 기능입니다. 유해성·권한·내부 정보·JSON 계약 검사를 모두 대신하지 않습니다. 공식 모델 설명은 영어 학습·평가 범위를 명시하므로 이번 한국어 63건의 결과를 다른 한국어 질문 전체에 일반화하지 않습니다. [IBM 모델 설명과 사용 예시](https://huggingface.co/ibm-granite/granite-guardian-3.1-2b).

다음 확인은 정상 답변의 오차단율과, 두 검사에서도 남은 34건에 대한 프로젝트 규칙 범위를 정하는 것입니다. 이번 업로드에는 실행·평가 코드, 새 profile, 모델 가중치, SSH 키·자격 증명, 서버 변경 사항을 포함하지 않습니다.
