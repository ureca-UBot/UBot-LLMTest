# 문장 의존관계 LLM 가드: 100건 기준선·112건 보완과 전체 차단 결정

2026-10-22 · RedHatAI/Qwen3-4B-Instruct-2507-quantized.w4a16 · 완료된 저장 실험만 게시.

**문장별 선택 프롬프트는 개선됐지만 채택 완료가 아닙니다. 최종 결정은 위험 검출 시 질문/답변 전체 차단입니다.** [정책 결정](report/policy_decision.md).

## 목표·대상·판정 기준

앞 문장에 의존하는 후속 문장을 안전하게 제거하면서 독립적인 정상 안내를 보존할 수 있는지 검사했습니다. 직접 작성한 기존 100건은 정상 답변40 + 문제·정상 혼합 답변60이며, 통신10영역 × 문장구성10유형입니다. 100개 독립 공격 유형이 아닙니다.

기준선 100회 호출 후 같은 100건과 추가 인용·정정 경계12건(정상6+혼합6)을 보완 프롬프트로 112회 검사했습니다. 두 실험 합계 212회 가드 모델 호출이며, 답변 생성·임베딩·별도 외부 Judge는 호출하지 않았습니다. 이전에 관찰한 같은 100건으로 보완한 개발 회귀 실험이므로 독립적인 운영 정확도 평가로 해석하지 않습니다.

실제 사용한 프롬프트: [기준선 문장별 v3](../../../prompts/output_guard/dependency_sentence_v3_20261022.txt) · [보완 문장별 v4](../../../prompts/output_guard/dependency_sentence_v4_20261022.txt). 둘 다 제품 미연결 실험 원문입니다. temperature0 / 동시 요청1 / 자동 재시도0이며 max_tokens는 기준선850, 보완1100입니다. 출력 계약이 달라진 비교이며 순수한 문구 변경만의 효과로 분리하지 않았습니다.

LLM은 원본 질문·답변 전체·근거 FAQ·문장 번호를 한 번에 받았습니다. 문장별로 독립 요청을 보내지 않았습니다. 기대 정답·기존 코드 삭제 번호는 모델에 전달하지 않았고 원문 구간만 선택했습니다. 메타데이터가 모델 판정을 덮어쓰지 않으며, REVIEW의 의존 문장 제외는 확정 탐지 성공으로 세지 않습니다.

## 같은 100건: LLM 단독 전후

| 항목 | 기준선 | 보완 후 |
|---|---:|---:|
| 정상 답변 전부 보존 / 40 | 30 | 34 |
| 혼합 답변 문제만 제거·정상 전부 보존 / 60 | 35 | 49 |
| 정상 문장 확정 오삭제 사례 / 100 | 22 | 11 |
| 문제 문장이 남은 사례 | 3 | 3 |
| 보류 | 12 | 4 |

원래 오삭제22건 중16건은 문제 제거와 정상 보존이 모두 맞았습니다. 5건은 확정 오삭제, 1건은 보류가 남았습니다. 전체 회귀에서는 새 정상 문장 삭제6건과 새 미탐1건이 생겼습니다. 미탐 합계는3건으로 같지만 사례 구성이 다르므로 기존 차단이 모두 유지됐다고 하지 않습니다.

추가12건은 정상 보존5/6, 혼합에서 문제만 제거·정상 보존2/6이며 실제 미탐2건이 남았습니다. 새 경계12건은 이전 프롬프트에서 검사하지 않았으므로 전후 회귀와 분리했습니다.

## 코드+LLM 재구성 비교

같은 모델 판정을 저장된 구형 문장 제거 코드 결과와 결합한 오프라인 재구성입니다. 결합용 추가 모델 호출이나 최신 전체 차단 코드 실행이 아닙니다. 코드가 이미 삭제한 정상 문장은 복원하지 않았습니다.

| 항목 | 기준선 | 보완 후 |
|---|---:|---:|
| 정상 답변 전부 보존 / 40 | 29 | 32 |
| 혼합 답변 문제만 제거·정상 전부 보존 / 60 | 37 | 51 |
| 정상 문장 확정 오삭제 사례 / 100 | 23 | 16 |
| 문제 문장이 남은 사례 | 1 | 0 |
| 보류 | 12 | 3 |

미탐0건도 보류3건과 정상 오삭제16건을 제외한 채 무조건 안전함을 뜻하지 않습니다. 전체 차단 정책의 안전성 결과로 대체하지 않습니다.

## 보완 내용·한계

발화 역할 → 해당 문장과 근거의 관계 → 실제 의미 의존관계 → 최종 판정 순서로 바꿨습니다. 특정 FAQ 번호·질문 ID 허용 예외는 없습니다. 정상 정정과 잘못된 인용에 대한 동의, 독립 안내와 앞 전제를 필요로 하는 결론을 혼동하는 한계가 남았습니다.

수작업 기대 정답과 저장 판정 기준의 비교이며 외부 Judge의 독립적인 전수 채점은 아닙니다. temperature0도 실행 환경 전체의 재현성을 보장하지 않습니다. 코드+LLM 결합은 저장된 이전 코드 결과를 재사용했으므로 현재 서비스와 같다고 해석하지 않습니다. 제품 소스와 실행 스크립트는 게시하지 않습니다. 원시 results.jsonl은 당시 기록을 유지하며, 의존관계에 따른 확정 삭제와 보류를 구분한 최종 집계는 scored-results.jsonl과 comparison-summary.json을 기준으로 합니다.
