# L4 상한 확대·다양화 질문 측정 (부분 결과)

내부 처리 상한과 외부 동시 요청 수를 분리해 측정했다. 각 엔진 안에서 모델 파일·이미지는 고정하고 컨텍스트 4,096·최대 출력 512토큰·스트리밍/keep-alive 조건을 유지했다. 목표는 지연 제한 없는 HTTP 완료 8 RPS다.

| 엔진 설정 | 최고 RPS | 외부 동시 요청 | 해당 단계 P95(초) | 모니터링 GPU 최대(GiB) | 8 RPS | 상태 |
|---|---:|---:|---:|---:|---|---|
| ollama_p8 | 1.70 | 16 | 11.79 | 7.21 | 아니오 | completed |
| ollama_p16 | 2.23 | 32 | 18.14 | 11.88 | 아니오 | completed |
| ollama_p32 | 2.23 | 32 | 22.30 | 20.71 | 아니오 | completed |
| vllm_s64 | 9.97 | 64 | 9.15 | 17.35 | 예 | completed |
| vllm_s128 | 8.23 | 256 | 32.26 | 17.40 | 예 | completed |

아직 전체 요청 범위를 완료하지 않았다. 미측정 상한: llamacpp_p16, llamacpp_p32, llamacpp_p8, sglang_r128, sglang_r64. 질문 다양화 대기 엔진: sglang, llamacpp.

SGLang·llama.cpp의 이미지 적재 공간을 확보할 실험용 vLLM 이미지 삭제가 자동 승인 검토에서 거부되어 실행하지 않았다. 검토 사유는 측정 승인만으로 기존 이미지 삭제·공유 사용 범위까지 승인됐다고 볼 수 없다는 것이다. 정확한 이미지와 소유권·컨테이너 참조 없음에 대한 읽기 전용 검토 기록을 남겼으며 삭제 승인 답변을 기다린다.
[이미지 삭제 범위 검토 기록](D:/finalproject/llm/l4/runs/l4_http_20261003_03/raw/vllm_image_deletion_plan.json)

질문 다양화는 짧은 조회·복수 근거·긴 문맥·대화 정정·금액 계산·모호성/충돌의 6종 각 50개, 총 300개다. 가장 긴 입력은 실제 AWQ 토크나이저 기준 1,352토큰이며 출력 예산을 포함해 컨텍스트 범위 안에 들어간다. 각 엔진의 확대 상한 중 최고 처리량 설정에서 같은 다양화 문항을 사용했다.

| 선택 설정 | 기존 질문 최고 RPS | 다양화 질문 최고 RPS | 다양화 최고값의 동시 요청 |
|---|---:|---:|---:|
| ollama_p16 | 2.23 | 1.87 | 16 |
| vllm_s64 | 9.97 | 9.03 | 64 |

단계별 완료 수를 원시 요청에서 다시 계산하고 실제 전송된 질문이 봉인한 문항과 일치하는지 확인했다. 모든 실행 종료 및 최종 감사에서 GPU 0 MiB·compute PID 없음·실험 컨테이너 없음·기존 서비스 보존을 확인했다.

최고값은 이번에 시험한 설정 중 관측치다. 문항별 입력·출력 토큰 수, 실패 건수와 지연은 상세 JSON에 들어 있다. 질문 구성이 바뀐 RPS를 기존 질문 RPS와 동일한 부하로 해석하면 안 된다. llama.cpp의 keep-alive 실패 및 각 엔진의 실제 적재/슬롯 로그도 함께 확인해야 한다.
