**기존 여섯 설정을 모두 측정했다. 서버 재시작으로 첫 다섯 설정과 마지막 vLLM32의 GPU UUID가 달라, 같은 세션의 엄격한 비교 완료로 표시하지 않는다. 아래 비율은 세션 간 관측 비교다.**

SGLang 상한 32는 8.17 RPS, vLLM 상한 32는 9.13 RPS를 관측했다. vLLM32는 외부 동시 요청 32에서 9.13 RPS였지만 64에서는 7.60 RPS로 내려갔다. 상한과 실제 외부 동시 요청 수는 별개의 변수다.

llama.cpp는 전체 466건 중 205건의 HTTP 완료 실패가 있었다. 재사용 소켓의 `socket hang up` 패턴이므로 최고 RPS만으로 엔진의 계산 성능을 해석하면 안 된다.

각 실행의 원시 요청 수·측정 시간 내 완료 수를 다시 계산해 보고서와 일치하는지 확인했다. 각 실행 종료의 GPU 해제 증거는 통과했으며 마지막 세션 최종 감사에서도 GPU 0 MiB·compute PID 없음·기존 서비스 상태 보존을 확인했다.
