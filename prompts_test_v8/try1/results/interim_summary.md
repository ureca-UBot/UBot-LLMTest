## 4. 판단

- **두 안 모두 채택하지 않는다.** 정답 77.7% → 70.5%(ck) · 77.6% → 72.2%(ck2), 둘 다 p<0.001.
- 공통 원인은 **evidence(와 status)를 answer보다 먼저 쓰는 순서**다. 먼저 고른 evidence가 비면 보류(PI·AR), 하나만 고르면 그 범위만 답함(MT), 확신이 없으면 PARTIAL(CE·NC). 본문 문구로는 일부만 막혔다(ck2: HR·NC 회복, PI·MT는 그대로 또는 악화).
- 얻은 것도 순서에서 나왔다: FAQ ID 노출 76 → 28·31(answer 전에 출처 칸이 채워짐), 환각 122 → 83(ck2), SR 91 → 96·97.
- calc 칸의 효과는 이 설계로 가를 수 없었다 — calc를 채운 226건에서 정답 135 → 128(+25/−32), 산술 실수 오답 10 → 13(failure_analysis 2절).
- **다음 안:** calc → answer → evidence_ids → status(기준선 순서에 calc만 추가 — calc 효과만 측정, 보류·범위 축소 연쇄 제거). FAQ ID 노출은 순서 대신 answer 작성 방식에서 다루고, 답에 쓴 FAQ의 부가 안내(요금·확인 경로·주의·다른 선택지) 완결성 문장과 조회 방법 문장 금지를 표적 스모크로 먼저 본다(failure_analysis 4절).
- calc 먼저 순서는 반복 루프(60초 타임아웃)가 answer 먼저보다 잦다(4 · 1건 vs 0~1건). 서비스에 쓰려면 출력 토큰 상한(`num_predict`)이 필요하다.
