## 4. 실패 원인 — (3) 매장 도구 메시지

v1 sub의 매장 쪽 실패 원인은 두 가지였다([v1 4-4절](../../../pipeline_test_v1/try1/results/all_summary.md#4-4-매장-도구-경로에서-statuses-스키마가-강제되지-않음) · [5-3절](../../../pipeline_test_v1/try1/results/all_summary.md#5-3-누출이-줄었지만-여전히-남는-이유) 4번): 도구 실패 메시지가 되묻기를 시킴, 도구 경로에서 statuses 스키마가 강제되지 않음. 이번 변경은 앞의 것만 다룬다.

실패 사유가 남은 ST 6건은 모두 매장 칸 ABSTAIN + 빈 answer + 사유별 코드 안내로 끝났다.

| 케이스 | subn1 | subs2 |
|---|---|---|
| ST-013·014·015·028 (장소 없음) | ABSTAIN + 일반 안내 "문의하신 내용은 현재 안내 자료로는 확인해 드리기 어렵습니다." | ABSTAIN + "매장을 찾을 기준 위치가 없어 조회하지 못했습니다. 위치 권한을 허용하거나 지역·역 이름을 알려 주세요." |
| ST-016 (장소 없음) | statuses 잘못됨 + 도구 지시문 독백 | ABSTAIN(올바른 statuses) + 위 위치 안내 |

## 5. 고지·누출 — (4) UNAVAILABLE_NOTICE

"제공되지 않았습니다" 꼴은 사라졌지만, 목록 문장의 "조회 결과에 없"을 따라 쓴 고지로 바뀌었다.

| 케이스 | subn1 | subs2 |
|---|---|---|
| UD-028 | "…이번 달의 데이터 사용량은 제공되지 않았습니다." | "…이번 달의 데이터 사용량은 조회 결과에 없으므로 확인할 수 없습니다." |
| UD-030 | "…이번 달 요금은 제공된 정보에 없습니다." | "…그러나 이번 달 요금은 조회 결과에 없어 확인할 수 없습니다." |
| UD-027 | "…사용량 데이터가 제공되지 않았기 때문에…확정할 수 없습니다." | "…사용자 정보에 요금, 데이터 사용량, 미납 정보 등이 포함되어 있지 않아…판단할 수 없습니다." |

- 고지 문장 틀을 없애는 목적은 이루지 못했다. UD 누출 3 → 4다. 문구를 바꿔도 모델은 섞인 경우에 고지를 쓴다(v2 결론과 같음). **프롬프트에 들어가는 문장이 어떤 꼴이든, 모델은 그 꼴을 빌려 고지를 만든다.**
- 전체 누출 62 → 66, 섞인 케이스 55/66 → 58/68, 이중 고지 59 → 62 — 1단계 n1 프롬프트의 누출(v2)이 그대로 남아 있다.
- 채점 누출 패턴은 "확인할 수 없"으로 이 꼴을 잡는다. "조회 결과에 없습니다"만 쓰는 꼴은 아직 패턴에 없다.
