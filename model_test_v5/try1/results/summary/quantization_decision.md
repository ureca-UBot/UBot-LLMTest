# 양자화·모델 판단 — Qwen3-4B-Instruct-2507 Q4_K_M

작성일: 2026-10-08 · 근거 자료: v5 try1 배치 `v5-try1-n100`, v4 재집계 배치 `v4-try1-n100` (모델당 1,400건)

## 결정

1. **Ollama 운영 기준 양자화는 Q4_K_M으로 한다.** Q8_0은 정확도 이득이 없고 느리다.
2. **튜닝 대상을 `qwen3:4b` OFF(Thinking-2507)에서 `qwen3:4b-instruct` Q4_K_M(Instruct-2507)으로 바꾼다.** 다만 키 순서 문제(3절)를 먼저 확인한다.
3. **Gemma는 QAT를 쓰지 않는다.** Gemma를 다시 볼 때는 Q4_K_M(`gemma3:4b`)을 쓴다.
4. **vLLM 동시성 테스트는 4bit(AWQ)를 주 후보로, FP8을 비교용으로 둔다.** 8bit의 정확도 이득이 없으니 FP8을 고를 이유는 처리량뿐인데, L4에서도 4bit가 처리량에서 유리할 것으로 예측했다.

이 문서는 다음 실험의 대상과 조건을 정한 것이며 최종 모델 선정은 아니다.

## 1. Q8_0 vs Q4_K_M — 정확도 차이 없음, 속도 손해

| 지표 (RT 제외 1,300행) | Q4_K_M | Q8_0 | 차이 |
|---|---:|---:|---|
| 정답률 | 77.5% | 78.8% | +1.3%p · 짝 검정 p=0.22 |
| 정답+근거+상태 | 70.5% | 71.9% | +1.4%p |
| 환각률 | 26.2% | 26.5% | +0.3%p · 짝 검정 p=0.85 |
| 같은 문항 판정 일치 | | | 85.4% (Q8만 정답 104 · Q4만 정답 86) |
| 평균 응답 / P95 | 2.61s / 4.75s | 3.49s / 5.98s | **×1.34** |
| 생성 속도 (TPS) | 63.5 | 45.7 | **−28%** |
| 가중치 크기 | 2.5 GB | 4.3 GB | ×1.7 |

- 항목별로는 PI(+12%p)·CF(+8)·MT(+6)에서 Q8_0이, AR(−9)·PS(−5)·RT(−16)에서 Q4_K_M이 높다. 전체 짝 검정이 유의하지 않아 항목별 차이는 항목당 100건의 표본 오차로 본다.
- 생성 속도 비(63.5 / 45.7 = 1.39배)는 "생성 단계는 메모리 대역폭이 병목이라 읽는 가중치 바이트에 비례한다"는 예측(가중치 1.7배, KV 읽기 포함 시 약 1.5배)과 맞는다. T4 순차 기준이다.

**FP8에 대한 함의.** Q8_0은 가중치만 8bit이고 FP8 W8A8은 활성값까지 8bit라, Q8_0이 원본(BF16)에 더 가깝다. 그런 Q8_0도 Q4_K_M보다 정확하지 않았으므로, FP8이 4bit보다 정확도에서 이길 가능성은 낮다. 남는 근거는 처리량이다. 그러나 L4 servingtest 분석에서 생성 단계가 대역폭 병목이었고, v4 프롬프트는 입력의 85~90%가 공유 시스템 프롬프트(prefix cache)라 FP8이 유리한 입력 처리 비중도 작다. 그래서 L4에서도 4bit(AWQ)가 처리량이 높을 것으로 본다. 동시성 테스트에서 이 예측을 확인한다.

**확인할 것.** Ollama Q4_K_M과 vLLM AWQ는 같은 4bit여도 양자화 알고리즘이 다르다. 동시성 테스트 때 AWQ로 v5 서브셋(예: 항목당 50건)을 생성·Judge해 Q4_K_M과 정확도가 같은지 확인해야 한다. 10/06 servingtest의 Gemma 커뮤니티 AWQ처럼 변환본이 원본과 크게 어긋날 수 있다.

## 2. Instruct vs Thinking-2507 OFF — 큰 차이, 단 출력 순서가 섞임

| 지표 (RT 제외, 같은 1,300문항) | v4 `qwen3:4b` OFF | v5 `qwen3:4b-instruct` Q4_K_M |
|---|---:|---:|
| 정답률 | 62.2% | **77.5%** (짝 검정 p<0.001, Instruct만 정답 306 · OFF만 정답 108) |
| 정답+근거+상태 | 31.3% | **70.5%** |
| 기대 상태 일치 | 55.9% | **87.0%** |
| 답했는데 근거 미기재 | 25.3% | **2.4%** |
| 되묻기 | 349건 | 209건 |
| 과잉 거부(OVER_REFUSAL) | 18 | **0** |
| 환각률 | **22.8%** | 26.2% (p=0.025) |
| 평균 응답 | **2.46s** | 2.61s |

v4에서 Qwen의 오답 원인으로 짚은 과잉 보류(빈 evidence_ids → ABSTAIN → 보류 문장)가 거의 사라졌다. PI 18% → 73%, CE 26% → 67%, UI 35% → 59%. 추론 전용 모델을 추론 OFF로 쓴 것이 v4 Qwen 결과의 큰 원인이었다고 볼 수 있다. 대신 답을 더 많이 하면서 환각률이 3.4%p 올랐다.

## 3. 먼저 확인할 것 — Instruct는 키 순서를 따르지 않았다

Instruct Q4_K_M·Q8_0 2,800건이 모두 `answer → evidence_ids → status` 순서로 출력됐다. 생성 요청의 JSON 스키마는 `evidence_ids → status → answer` 순서였고, 같은 서버·같은 Ollama 0.34.2에서 Gemma QAT와 v4 두 모델은 스키마 순서를 지켰다. status 값은 다섯 개 안에서만 나왔다. 원인은 확인하지 않았다.

- v4의 출력 설계("근거를 먼저 고르고 그 근거로 상태를 정한 뒤 답한다")가 Instruct에서는 작동하지 않았다. 2절의 개선에는 모델 차이와 출력 순서 차이(답을 먼저 쓰고 라벨을 나중에 붙임)가 섞여 있다. status-본문 일치가 높은 것(90~92%)도 답을 먼저 쓴 영향일 수 있다.
- prompts_test_v1~v3의 튜닝은 Thinking-2507 OFF에서 했으므로 Instruct에 그대로 옮겨지지 않을 수 있다. 특히 v1~v3이 다룬 과잉 보류 문제는 Instruct에서 이미 대부분 사라졌다.
- 다음 프롬프트 튜닝 전에 할 일: ① 작은 스모크(예: 20건)로 Ollama가 이 모델에서 `format` 스키마의 키 순서를 강제하는지 다시 확인한다. ② 강제되지 않으면 "답 먼저" 순서를 Instruct의 기준선으로 받아들일지, 키 순서를 강제할 다른 방법을 찾을지 정한다. ③ 정한 순서로 Instruct 기준선을 확정한 뒤 v1~v3 개선안 중 남은 문제(환각, AR·CF·UI)에 해당하는 것만 다시 시험한다.

## 4. Gemma QAT vs Q4_K_M — QAT를 쓸 이유가 없다

| 지표 (RT 제외, 같은 1,298문항) | v4 `gemma3:4b` Q4_K_M | v5 `gemma3:4b-it-qat` |
|---|---:|---:|
| 정답률 | 64.5% | 67.0% (p=0.065) |
| 환각률 | **24.3%** | 31.7% (p<0.001) |
| 정답+근거+상태 | **44.8%** | 42.0% |
| status-본문 일치 | **76.8%** | 72.7% |
| 답했는데 근거 미기재 | **1.1%** | 8.2% |
| 평균 응답 / TPS | **1.88s / 60.8** | 2.18s / 56.6 |
| 파일 크기 | **3.3 GB** | 4.0 GB |

QAT는 정답률이 조금 높지만 유의하지 않고, 환각·라벨 정합·속도는 모두 나쁘다. 10/06 servingtest에서 QAT를 옮긴 커뮤니티 AWQ가 BF16과 크게 어긋났던 것도 함께 고려하면, Gemma 4bit는 Q4_K_M이 낫다. Gemma 계열은 v5에서 Qwen Instruct보다 정답률이 10.5~11.8%p 낮아(Q8_0 대비 짝 검정 p<0.001) 튜닝 대상에서도 뺀다.

## 5. 판단을 다시 볼 조건

- 키 순서 스모크(3절)에서 Instruct가 스키마 순서를 지키게 됐을 때 정답률이 크게 떨어진다 → 2절 판단을 출력 순서 효과로 다시 본다.
- vLLM 동시성 테스트에서 AWQ의 정확도가 Q4_K_M보다 뚜렷이 낮다 → FP8을 정확도 기준으로 다시 검토한다.
- 동시성 테스트에서 FP8 처리량이 AWQ보다 높게 나온다 → 4bit 우선 판단을 다시 본다.
- Instruct의 환각 증가(26%)가 프롬프트로 줄지 않는다 → `qwen3:8b` 등 상위 모델로 넘어간다(v4 계획의 확장 경로).

## 6. 집계 방법

- 모두 RT를 뺀 행 기준이다. 짝 비교는 두 run에서 모두 채점된 같은 문항만 쓰고 McNemar 정확 검정(양측)을 했다.
- v4 두 모델은 n200 run의 100 서브셋을 원본 그대로 가져오고 기존 판정을 입력 해시 대조 후 옮겨 재집계했다([v4_comparison.md](v4_comparison.md) 서두).
- 지연·TPS는 `format_performance.jsonl`(T4, 순차 단일 요청)의 값이다.
