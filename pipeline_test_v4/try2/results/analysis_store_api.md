# pipeline_test_v4 try2 — sub vs slot: 매장·사용자 정보(API) 케이스 (2026-10-23)

[analysis_no_store_api.md](analysis_no_store_api.md)에서 뺐던 165건을 따로 본다. 두 경로는 출력 형식을 아직 고정하지 않았고 status도 ABSTAIN으로 고정된 상황이라 FAQ 경로와 섞지 않았다. 해석할 때 그 점을 감안한다.

**한 줄 요약: 매장은 slot이 도구 경로 실행 오류(LLM-005 12건)를 없애 정답 수가 크게 늘었다. 사용자 정보는 고지가 거의 사라지고 정답이 오르는 방향이다. 두 경로 모두 "자료에 없음"을 "없다·안 된다"로 단정하는 문제가 FAQ 경로와 같은 모양으로 나타났고, 사용자 정보에서는 "미납 정보 없음"이 "밀린 요금 없음"으로 읽히는 위험한 사례가 있다.**

## 0. 범위와 기준

- run·모델·Judge는 [analysis_no_store_api.md](analysis_no_store_api.md) 0절과 같다(`pv4-try2`, `qwen3:4b-instruct-2507-q4_K_M`).

  - 매장 도구 실패 메시지는 "매장 하위 질문은 ABSTAIN으로 두라"이고, 위치 안내는 코드가 붙인다(`store_failure`).

### 2-6. 문제가 생길 수 있는 부분

**① "조회 결과에 없음"을 "없다"로 읽음 (UD-009) — 운영에서 가장 위험한 형태**
- 질문 "제가 밀린 요금이 있나요?"에 slot은 `ANSWER`로 "요금 밀린 정보가 없습니다. 현재 조회 결과에 미납 정보나 요금 관련 데이터가 없습니다."라고 답했다.
  - sub는 ABSTAIN이었고, 코드 안내 "문의하신 내용은 현재 안내 자료로는 확인해 드리기 어렵습니다."만 나갔다.
- Judge는 정답·근거 있음으로 봤지만, 사용자는 "밀린 요금이 없다"로 받아들일 수 있다.
  - 실제로는 미납 정보를 조회하지 않은 것이다(`UNAVAILABLE_NOTICE` "다음 항목은 조회 결과에 없음: 요금, 데이터 사용량, 미납 정보").
- "없는 항목" 목록 문구가 "값이 없음(0건)"으로 읽힐 여지가 있다. FAQ 경로의 부정 단정과 같은 원인(answer를 먼저 쓰고 그 문장을 보고 ANSWER)이다.

sub에서 "ABSTAIN인데 본문에 단정"이던 것이 slot에서 "ANSWER로 단정"으로 바뀐 경우가 많다. 내용은 같고 라벨만 바뀌었다. 사용자에게는 두 안 모두 단정이 나간다.

**③ 가입일 계산을 과잉 보류함 (UD-001, 두 안 공통)**
- "제 Ubot 가입 기간이 얼마나 됐어요?"에 slot 칸은 "가입일은 2026-10-20입니다. 그러나 이 날짜는 미래 날짜로, 실제 가입 기간은 확인할 수 없습니다. 따라서 Ubot 가입 기간은 불가능하게 확인됩니다."(ABSTAIN)라고 썼다.
- 모델이 오늘 날짜를 모른다. 가입일 계산 문항은 프롬프트에 기준 날짜가 들어가야 답할 수 있다. 출력 형식과 상관없는 입력 쪽 문제다.

**④ ANSWER 칸 안에 다른 FAQ를 끌어오고 고지까지 씀 (MT-016, 유일한 이중 고지)**
- "최초 7일은 무료로 임대폰을 이용할 수 있습니다. 분실 시에는 단말 할부금이 … 보험 보상은 분실일로부터 60일 안에 … 그러나 변상금 금액에 대한 구체적인 금액은 FAQ에 명시되어 있지 않습니다."
- 첫 칸(무료 기간)에 둘째 하위 질문(변상금) 이야기를 끌어왔고, 뒤에 코드 안내가 또 붙었다. 칸을 나눠도 한 칸이 다른 하위 질문까지 다루면 고지·끌어오기가 그대로 나간다.

**⑤ 표기 오류**
- OS-016: "플러스 2GB -13,000원"처럼 기호가 잘못 들어갔다(Judge는 지어냄으로 봄).
- MP-023: "로밍 패가 사용이 시작되지 않았을 경우"처럼 단어가 깨졌다.
- 빈도는 낮지만 slot에서만 보였다.

## 3. 판단

| | 매장 | 사용자 정보 |
|---|---|---|
| slot이 나은 점 | 실행 오류 12 → 0, 정답 19 → 27, 실패 안내 정상 | 고지 32 → 2, 이중 고지 31 → 1, 정답 +5 |
| slot의 위험 | 칸 수 초과 6건(안내 누락), 공항 유심 부정 단정 3건 | "조회 결과에 없음" → "없다" (UD-009), 부정 단정 4건 |
| 공통 원인 | answer를 먼저 쓰고 그 문장을 보고 ANSWER를 붙임 + "'불가하다'도 ANSWER" 기준 | 같음 |

- 두 경로 모두 slot으로 바꿔도 FAQ 경로와 같은 방향이다. 고지·오류는 확실히 줄고, 단정 환각이 "모두 ANSWER" 안으로 들어온다.
- 매장·사용자 정보에만 있는 추가 과제:
  1. **칸 수 초과 처리:** 스키마가 강제되지 않는 도구 경로용. 매장 실패 사유가 있으면 칸 정합과 관계없이 안내를 붙이는 방안을 검토한다.
  2. **`UNAVAILABLE_NOTICE` 문구:** "조회하지 않은 항목"이 "값 없음"으로 읽히지 않게 바꾼다(예: "조회하지 않음"). 바꾸면 develop `AiOutputGuardService.MISSING_LOOKUP_DATA` 패턴도 함께 맞춘다(NEXT_TRY 2-2).
  3. **오늘 날짜 제공:** 가입일·약정 계산 문항(UD-001 등)용. 출력 형식과는 별개다.
- 라벨은 Claude가 작성했고 사람 검수 전이다. 매장 Judge는 도구 결과를 정답 기준으로 본다(pipeline-judge-2).
