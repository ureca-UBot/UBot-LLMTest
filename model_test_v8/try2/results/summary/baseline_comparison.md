## 같은 조건과 두 가지 비교

1. **새 전체 경로 1,000건:** 현재 입력 가드, 새 임베딩·검색, 새 LLM 답변, 출력 가드를 EC2에서 실행했습니다. 원문 질문·FAQ 자료·지정 RedHatAI 가중치·프롬프트·JSON schema·온도 0은 try1과 같습니다. 리랭커·직접 반환 캐시는 OFF입니다.
2. **저장된 기준점 본문 1,000건 재검사:** try1의 실제 질문·제공 FAQ·원문 답변을 현재 출력 가드에 그대로 전달했습니다. LLM 호출은 0회이며 결과는 710건 유지, 239건 정리, 51건 차단입니다. 입력·새 생성의 변화와 출력 가드의 영향을 구분하는 자료입니다.

## 완전히 같은 요청이 아닌 8건

입력 가드에서 7건에 내용 삭제 없이 줄바꿈을 추가했습니다. CORE-0217·0452·0737·0912·0962·0964·0965입니다. [원문과 처리 후 질문](../report/input_format_changes.json).

CORE-0294는 실제 임베딩 검색의 3위 FAQ가 try1의 58에서 try2의 804로 달랐습니다. 1·2위는 294·241로 동일합니다. 이 사례를 완전히 동일한 Context 비교로 취급하지 않았습니다.

실제 HTTP 요청 전체가 같은 사례는 992건, model·schema·temperature·stream 등 질문/FAQ 이외 생성 파라미터는 1,000건 모두 같습니다. 새 LLM 본문 자체는 993건이 기존 본문과 같습니다. 응답의 의미가 같다는 판정을 993건으로 대신한 것은 아니며 정확한 본문 문자열 일치입니다.

## 기존 판정 참고표의 한계

기존 Judge 원판정은 정답 633·오답 367건입니다. 원판정과 분리 보관된 Codex의 FAQ 대조 재검토를 반영한 참고 의견은 정답 702·오답 298건입니다. 이 참고 분류로 기준점 재검사 결과를 나누었으며, 새 최종 답변을 전수 재판정한 것이 아닙니다.

이전 오답으로 분류된 본문과 제공 FAQ가 같고 최종 본문도 그대로 남은 사례는 138건입니다. 가드가 모든 내용 오류를 잡았다는 의미로 해석할 수 없습니다. 반대로 이전 정답 분류 답변 7건이 전체 차단됐지만 일부는 정상 설명과 실행 근거 없는 약속이 섞여 있어, 7건 전체를 완전히 정상인 답변의 오차단으로 단정하지 않았습니다.

성능 수치 711·238·51은 정답·부분 정답·오답 점수가 아닙니다. 전체 내용 정확도·근거 이탈 개선은 같은 평가 기준의 후속 전수 Judge와 FAQ 대조 후 판단해야 합니다. 이전의 1,600문항 공격 세트와 이번 정상 원본 1,000건은 서로 다른 테스트입니다.
