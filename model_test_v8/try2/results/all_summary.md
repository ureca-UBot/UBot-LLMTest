## 0. 무엇을 테스트했나

try1과 같은 정상 FAQ 원본 질문 1,000개에 **입력 가드 → 실제 BGE-m3 임베딩 → FAQ 검색 → RedHatAI LLM → 출력 가드**를 적용했습니다. 생성 모델·프롬프트·검색 조건을 기준점과 맞춘 후, **사용자가 받은 최종 답변**을 같은 팀 Judge 기준으로 평가했습니다.

| 구분 | 항목·분모 | 현재 상태 |
|---|---|---|
| 내용 평가 | 정확성·근거 없는 추가·누락·정보 부족 대응 / 최종 답변 1,000개 | Judge 정답 614/1,000 · 근거 이탈 161/1,000 |
| 가드 처리 | 질문 1,000개·생성 답변 1,000개 | 입력 수락 1,000 · 출력 수정 없음 711 · 출력 수정 후 반환 238 · 차단 안내 반환 51 |
| 보조 라벨 | 모델 status·evidence_ids / 답변 1,000개 | 기록 보관, 내용 정답 판정과 구분 |
| 검색 확인 | 원본 FAQ top1·top3 / 원본 질문 1,000개 | 자체 일치 1,000건 |
| 형식 관찰 | FAQ 번호 노출 / 최종 답변 1,000개 | 3건 (0.3%). 한 답변에 여러 번호가 나와도 1건 |
| 계측 | LLM·파싱·출력 검사 요청 시간 / 1,000회 | 기록 완료. try1의 LLM 요청 시간과 범위가 다름 |

**“답변 수정 없음”은 정답이라는 뜻이 아닙니다. “답변 수정 후 반환”도 오류를 고쳤다는 뜻이 아닙니다.** 둘 다 가드가 답변을 어떻게 처리했는지 나타내며, 맞고 틀림은 아래의 **내용 정확도 평가**를 보세요. [처리 용어와 실제 정답 수](#6-가드-처리-용어와-세부-건수).

개인·매장 조회 API 자료·도구·대화 이력은 제공하지 않았습니다. 실제 개인 값이나 특정 매장 정보를 확인할 수 없다고 적절히 안내하는 답변은 정상일 수 있습니다.
