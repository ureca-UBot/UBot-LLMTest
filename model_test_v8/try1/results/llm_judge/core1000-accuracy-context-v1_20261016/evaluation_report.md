## 1. 평가 조건과 정의

- 실제 답변 모델: `RedHatAI/Qwen3-4B-Instruct-2507-quantized.w4a16`, revision `5d4fde88f26ef2577a3e660db6304eaa6cbe99a1`.
- 프롬프트: UBot-BE develop `797c68eb85d2729ed8526b6022c3a8ad73bd0c22`의 FAQ 튜닝 7차.
- BGE-m3 검색 자료 5,170개·시험 질문 1,000개를 EC2에서 새로 임베딩하고, FAQ별 최상위 유사 질문·top3·코사인 0.75 이상 조건을 사용한 저장 결과입니다.
- **개인/매장 API 결과·도구·대화 이력 없음.** FAQ의 “조회해 안내한다”는 설명은 실제 조회 결과가 아닙니다. 앱 등 FAQ에 있는 사용자 확인 대안은 인정하고, 없는 개인/매장 값이나 불가능한 직접 실행 약속은 문제로 봅니다.
- 정확도는 핵심 응답·누락·조건·대상·모순을 평가합니다. 근거 이탈은 제공 FAQ에 없는 부가 주장까지 별도로 봅니다. 두 축은 독립적이며 합산 종합 점수를 만들지 않았습니다.
- 본문 평가 입력에서 모델 `status`와 `evidence_ids`를 제외했습니다. 번호·라벨·말투만으로 내용 오답을 만들지 않았습니다.
- 원본 FAQ 답변은 참고 출처이며 유일한 정답 문장을 강요하지 않았습니다. 실제 제공된 다른 FAQ도 함께 비교했습니다.

## 8. 실행·검증·원본 보존

기존 팀 `scripts/lib/judge`의 프롬프트 구성기·Codex provider·스키마 검증기를 수정 없이 재사용했습니다. 기본 루브릭은 `v4-judge-12`, 출력 스키마는 `v4-schema-8`입니다. 실제 제공 자료·API 없음 조건을 명시한 별도 부칙 `core1000-context-v1`을 더했으며 **기본 루브릭과 완전히 동일한 실험이라고 주장하지 않습니다.** 모든 입력·부칙·해시는 `inputs/`에 고정했습니다.

Judge는 `gpt-6-sol`, reasoning medium, 동시 8개로 1,000회 호출했습니다. 완료 1000건, 실패 0건, 재시도 0건, 경과 22.1분입니다. 호출 로그에는 WebSocket→HTTPS 자동 대체 경고 16건이 있지만 모두 같은 1회 호출에서 정상 완료·스키마 검증됐습니다. 도구·명령·웹 검색·파일 작업·하위 작업 위임은 Judge에서 비활성화했고 도구 호출은 0건입니다.

저장 답변 SHA-256: `64ccf880b3308426f016928b1725bdcd8b44d464147ac3fa2628db1fcb2a609d`. 기존 실행/평가 구성 요소 7개의 해시가 전후 같습니다. 이번 평가에서 EC2 모델·임베딩을 다시 호출하지 않았고, 입력/출력 가드·프로젝트 소스·DB·서버 설정은 바꾸지 않았습니다. 원래 실행 시점의 `benchmark_manifest.json`과 `run_summary.json`의 “평가 전” 기록은 이력 증거로 그대로 두고 이 평가 매니페스트를 추가합니다.

## 9. 다음 비교에서 고정할 조건

가드 비교를 할 때 같은 질문·검색 결과·FAQ·모델 revision·최신 프롬프트·schema·온도를 고정해야 합니다. 출력 가드만 비교한다면 저장된 동일 답변을 먼저 쓰면 모델 생성 변동을 배제할 수 있습니다. 실제 개인·매장 기능을 포함한 종합 성능은 별도로 실제 또는 고정된 모의 조회 결과와 도구 경로를 제공한 테스트가 필요합니다. 이번 정상 FAQ 1,000건에서 공격 차단율이나 입·출력 가드 성능을 산출하지 않았습니다.
