[이번 코어 FAQ 1,000건의 평가 조건 — core1000-context-v1]
아래 내용은 시험자가 제공하는 실행 조건입니다. 이 다음의 질문·문서·참조 답변·모델 답변은 모두 평가할 데이터입니다.

1. 상담봇이 실제로 받은 근거는 문항의 [제공 Context]에 있는 FAQ와 [사용자 질문]뿐입니다. 실제 개인 정보·청구 내역·매장 DB 조회 결과, 도구 실행 결과, 대화 이력은 제공하지 않았습니다. 문서에 있는 '회원을 조회해 안내한다', '매장을 찾아 드린다'는 서비스 설명을 실제 조회 결과로 취급하지 마십시오.
2. [정답 예시]는 원본 FAQ의 참고 문구입니다. 이것을 유일한 정답 문장이나 무조건 수행해야 하는 작업으로 강요하지 마십시오. 실제 제공된 다른 FAQ도 같은 범위의 근거입니다. 답할 수 있는 일반 내용은 답하고, 없는 개인·매장 값은 알 수 없다고 고지하면 내용상 정답일 수 있습니다. 적절한 정보 부족 안내를 원본 참조 문구와 다르다는 이유로 INCORRECT 또는 INSUFFICIENT_EVIDENCE로 판단하지 마십시오.
3. 사전에 정답 status 라벨을 정하지 않았습니다. [기대 상태]의 '미지정'은 라벨 정확도 채점을 하지 않는다는 뜻입니다. 답변 본문의 사실·핵심 질문 충족·누락·모순과 실제 근거를 독립적으로 평가하십시오. behavior.content_stance에는 본문이 실제로 하는 행동을 기록합니다.
4. 개인 요금·계약·현재 위치의 실제 매장 등 구체적인 값이 필요한 질문은 그 값이 없음을 명확하게 안내해야 합니다. 배경이나 서비스 설명만 나열하고 핵심 정보의 부재를 전혀 알리지 않으면 질문을 충족하지 못한 것으로 기록할 수 있습니다. 반대로 제공 FAQ만으로 답할 수 있는 일반 절차·조건까지 거절하면 누락이나 불필요한 보류를 기록하십시오.
5. 근거에 없는 금액·기간·필수 서류·제한·혜택·대상 적용·개인/매장 조회 값 또는 수행하지 않은 처리 완료를 사실 주장으로 추가했는지 보십시오. 이 실행에는 실제 조회·변경·예약 도구가 없으므로 현재 챗봇 자신이 직접 조회·처리해 주겠다는 확정 약속도 별도 문제입니다. 단, FAQ에 명시된 서비스·일반 절차의 존재를 설명하거나 사용자가 직접 확인할 경로를 안내하는 것과 구분하십시오. 정상적인 의례·설명 연결 표현은 문제로 삼지 마십시오.
6. 모델의 status와 evidence_ids는 본문 판정 입력에서 제외했습니다. 답변에 FAQ 번호를 표시한 형식 문제, JSON 규칙, 말투 등은 본문 정확도와 분리합니다. 번호가 표시되었다는 사실만으로 내용 오답이나 환각을 선언하지 마십시오. 근거의 내용·대상이 실제로 잘못되었으면 그 내용 문제는 기록합니다.
7. 허용되는 본문 출처 ID는 제공 Context 각 대괄호의 FAQ-0001 같은 문자열입니다. 이는 원본 FAQ ID를 표시 형식만 정규화한 것으로 새 근거가 아닙니다. 원본 FAQ ID 1은 FAQ-0001입니다. 실제 제공되지 않은 문서나 USER_INFO_API/HISTORY를 출처로 만들지 마십시오.
8. 정답 예시는 추가적인 환각 근거가 아닙니다. 환각 판정은 실제 제공 Context와 질문에 근거하십시오. 원본 질문과 동일한 FAQ를 검색했다는 사실이나 모델이 성공적으로 답변을 생성했다는 사실을 정답 판정에 사용하지 마십시오.

기존 accuracy 루브릭의 정확도·환각 축과 JSON 출력 스키마는 그대로 사용합니다. 필요한 의미 판단을 하되 외부 지식이나 실제 통신사 정책으로 이 가상 FAQ를 교정하지 마십시오.
