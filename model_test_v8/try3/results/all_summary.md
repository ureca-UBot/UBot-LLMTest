# 최신 FAQ 질문과 입력 가드 보완 및 가드 제외 LLM 실행

최신 FAQ 질문 1,000개, 같은 2,600건을 사용한 입력 가드 보완, 가드 없이 EC2 임베딩·LLM을 실행한 결과를 모았습니다. **입력 검사 결과와 LLM 생성 결과는 별도 실험이며 합산 정답률·방어율을 계산하지 않았습니다.** 이번 게시에서는 기존 결과를 정리했으며 테스트·LLM·Judge·DB를 다시 실행하지 않았습니다.

## 구성과 평가 기준

| 자료 | 대상과 실제 확인 | 읽기 시작점 |
|---|---|---|
| 최신 FAQ 질문 | 원문 1,000개, GENERAL 724·USER_DATA 276, 전체 검색 자료 1,688 FAQ·8,443 표현 | [질문·엑셀·선정 기준](../questions/README.md) |
| 입력 가드 | 정상 1,100 + 직접 입력 공격 1,400 + 검색 문서 공격의 정상 입력 100 | [보완 전후 결과](input_guard/README.md) |
| EC2 기준 실행 | 최신 질문 정리·멀티턴 코드·프롬프트 유지, 우리 입력·출력 가드 제외 | [모델·실행 결과](llm_baseline/README.md) |

입력 가드는 문제 요구 제거 후 정상 부분이 남았는지 확인했습니다. LLM 쪽은 검색·근거 선별·호출·응답을 기록한 실행 결과이며 **내용·안전성 Judge는 미실행**입니다. 모델의 ANSWER 상태를 정답으로 사용하지 않았습니다.

## 전체 결과

- 입력 검사: 문제 요구 제거·정상 질문 보존 **814 → 1,390건 / 직접 입력 공격 1,400건**. 잔존 586 → 10건. 같은 정상 1,100건의 내용 삭제·전체 질문 종료는 0건.
- 입력 회귀: 마지막 저장 실행에서 **2,159개 테스트 통과**. 같은 자료를 보며 보완한 결과로 독립된 일반화 점수는 아닙니다.
- LLM 기준 실행: **1,000건 처리, 답변 생성 964·근거 선별 후 미응답 22·매장 도구 경로 제외 14**. 생성 964건을 정답 수로 세지 않습니다.
- 연결 중단 전 863건을 보존하고 137건만 재개했습니다. 연결 장애 구간은 최종 실행 결과에서 제외했습니다.
- 가드 코드·실행 엔진·평가 코드·프롬프트 파일을 변경하거나 게시하지 않았습니다. 기존 회차도 덮어쓰지 않았습니다.

## 이전 회차와 비교할 때

[기존 가드 적용 2,600건](../../try2/results/full_pipeline/full2600-instruct2507-20261019/README.md)은 이전 1,034 FAQ·5,170 표현과 입력·출력 가드를 사용한 결과입니다. 이번에는 최신 1,688 FAQ·8,443 표현을 사용했고 질문 집합과 최신 질문 정리 흐름도 달라졌습니다. 이번 생성 964건을 과거 Judge 정답 수와 비교해 성능 변화라고 결론 내릴 수 없습니다.

이번 정상 원문 1,000개 중 463개는 이전 FAQ 1,034개 이후 추가된 항목에서 선정됐습니다. 실제 회원·매장 자료를 주지 않은 조건과 문항별 대화 이력 0턴도 함께 읽어야 합니다.

## 남은 문제와 해석 범위

입력 가드에는 합의한 변경 범위에서 제외한 구독·가사 요구 10건이 남아 있습니다. 검색 문서 공격 100건의 정상 사용자 입력 보존을 문서 공격 방어 성공으로 계산하지 않습니다. 실제 임베딩·LLM·출력 단계를 합친 재평가는 이번 입력 검사에 포함하지 않았습니다.

가드 없는 LLM에서도 근거 선별로 정상 답의 자료가 빠지거나 근거 없는 설명을 덧붙이는 사례가 확인됐습니다. [대표 사례](llm_baseline/observations.md)와 [미응답·제외 36건](llm_baseline/unanswered_and_excluded.md)에 실제 질문과 근거를 남겼습니다. 이번 자료로 출력 가드 문제가 모두 해결됐다고 결론 내리지 않습니다.
