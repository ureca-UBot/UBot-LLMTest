# 저급 모델 프롬프트 제어 튜닝 후보 선정

생성일: 2026-09-30 · 근거: [test2(v2 try2) `hallucination_cause.md`](../../../../model_test_v2/try2/results/summary/hallucination_cause.md) · [test3(v3 try1) `hallucination_cause.md`](hallucination_cause.md) · 두 문서의 원인 분류(A/B/P/S/M)와 13개 문항 유형 집계를 그대로 인용해 "프롬프트 제어로 고치기 쉬운가"라는 새 잣대를 얹는다.

## 0. 결론 먼저

- **튜닝 방식은 파인튜닝이 아니라 프롬프트 제어(규칙 추가·상태 정의 보강·few-shot)를 최우선으로 한다.** 이 문서의 난이도 등급은 두 `hallucination_cause.md`의 "파인튜닝 기대" 열과는 다른 기준이다 — 판단 자체가 맞았는지(쉬움) vs 판단 자체가 틀렸는지(어려움)를 가른다.
- **저급 모델 후보 3종 — gemma3:4b · exaone3.5:7.8b · qwen3:1.7b — 중 프롬프트 제어 튜닝 1순위는 `gemma3:4b`다.** 이 모델은 두 라운드(test2·test3) 모두에서 순수 판단 오류(B1, "답 없는데 있다고 오판")가 2~3%로 극히 낮고, 실패의 대부분(판정 불가의 93% 이상)이 모델 능력이 아니라 **프롬프트의 상태 정의 공백**(ABSTAIN↔CLARIFY 구분 기준 없음)에서 나온다. 스펙만 채워도 성적표가 크게 바뀔 가능성이 가장 큰 모델이다.
- **2순위는 `exaone3.5:7.8b`다.** 자각형 위반(A1+P) 비중이 세 모델 중 가장 높아(25~27%) 규칙 강화 효과가 직접적이지만, 과대 판단(B1, 12~16%)과 과소 판단(B4, 16~22%)이 동시에 크게 존재해 한쪽을 프롬프트로 누르면 반대쪽이 늘어나는 트레이드오프를 관리해야 한다.
- **`qwen3:1.7b`는 프롬프트 튜닝 우선순위가 가장 낮다.** 두 라운드, 추론 ON/OFF 모든 조건에서 순수 판단 오류(B1)가 35~45%로 압도적 1위를 유지한다. 프롬프트 규칙을 아무리 강화해도 "컨텍스트에 답이 있는지 자체를 못 알아채는" 문제는 잘 움직이지 않는다. 용량 한계일 가능성이 커 대조 데이터 학습(SFT)이 더 맞는 접근이다.
- 참고로 이미 상위 후보군(gemma3:12b, qwen3:4b/8b/14b)도 같은 틀로 함께 표에 실었다 — `model_selection.md`에서 이미 1차 MVP로 뽑힌 모델들이라 "저급 모델 교체" 논의의 직접 대상은 아니지만, 등급 비교의 기준선으로 쓴다.

## 1. 목적과 등급 기준

**목적**: 저급 모델 중 프롬프트 제어만으로 개선 여지가 큰 모델을 골라, 파인튜닝 없이 먼저 시도할 대상을 정한다.

**저급 모델 후보**: v2(test2)·v3(test3) 양쪽에 공통으로 존재하는 `gemma3:4b` · `exaone3.5:7.8b` · `qwen3:1.7b` 세 모델. `qwen3:4b/8b/14b`, `gemma3:12b`는 이미 1차 선별을 통과한 상위 후보군이라 이 문서의 "교체 대상 선정" 논의에서는 제외하되, 비교 기준선으로 함께 표시한다.

**난이도 등급**

| 등급 | 의미 |
|---|---|
| 상 | 명시적 규칙 한두 줄 추가로 즉시 개선 기대. 판단은 맞았거나(A1), 이미 정의 공백이 원인(교차)인 경우 |
| 중상 | 임계값·체크리스트 성격의 규칙으로 상당 부분 개선 기대. 다만 반대 방향 오류가 늘 위험 있음 |
| 중 | 규칙을 넣어도 식별·구분 능력 자체가 걸리는 경우. 부분적 개선만 기대 |
| 하 | 컨텍스트 이해·판단 능력 자체의 문제. 프롬프트로 잘 움직이지 않음 |
| 해당없음 | 문항·채점 기준 문제이거나 표본이 너무 적어 모델 튜닝 논의 대상이 아님 |

## 3. 환각 외 오답(S·M) 항목별 프롬프트 제어 난이도

환각이 없는데도 틀린 답변(Judge 근거 4~5점이지만 오답)을 status 오류(S)와 내용 누락(M)으로 나눈 결과다. 두 문서의 7절 기준이다.

| 항목 | 정의 | 난이도 | 근거 |
|---|---|---|---|
| S — 과소 판단 | 기대보다 물러남(예: 기대 ANSWER → PARTIAL) | 중상 | B4와 같은 방향·같은 성격. "정보가 다 있으면 끝까지 답하라"는 규칙이 직접 겨냥한다 |
| S — 과대 판단 | 기대보다 넓게 답함(예: 기대 ABSTAIN → ANSWER) | **하** | B1과 같은 방향. 본문에 근거 없는 내용은 없지만 "답할 수 있다"는 판단 자체가 틀렸다 — 판단력 문제 |
| S — 보류 계열 교차 | ABSTAIN↔CLARIFY·OUT_OF_SCOPE 교차 | **상** | 환각 쪽과 동일한 명세 공백. 이 절 S의 24~53%가 이 교차라(모델마다 다름) 스펙 정의만으로 상당수 해소 |
| M — 공통 누락(FIX·CHK 문항) | 여러 모델이 같은 문항에서 같은 내용을 빠뜨림, 문항 검토에서 수정 필요·경계 판정 | 해당없음 | test2 58%, test3 67%가 여기 해당 — 모델 문제가 아니라 문항의 "필수 사실 기준"이 불명확한 문제. 문항 수정이 먼저다 |
| M — 개별 누락(적합·미검토 문항) | 적합 판정 문항에서 그 모델만 빠뜨림 | 중 | 작은 모델(Qwen3 1.7B, Gemma3 4B)에 집중된다. "질문과 관련된 조건·기준값·예외를 답변에 빠짐없이 포함하라"는 체크리스트 규칙으로 일부 개선 기대 |

## 5. 모델별 프롬프트 제어 튜닝 난이도 요약

분류 대상(환각 답변 − C) 대비 비율. "쉬움 지표" = A1+A2+P(규칙 재강조로 직접 개선), "중상 지표" = B4(임계값 조정), "어려움 지표" = B1(판단력 자체 문제), "교차 비중"은 판정 불가 중 스펙 공백(ABSTAIN↔CLARIFY·OUT_OF_SCOPE)이 차지하는 비율이다.

**해석**

1. **gemma3:4b는 B1이 두 라운드 모두 2~3%로, 저급 모델 후보 중 가장 낮다.** 판단력 자체는 크게 나쁘지 않다는 뜻이다. 대신 판정 불가(전체 환각의 55~56%)가 압도적으로 큰데, 그중 93% 이상이 ABSTAIN↔CLARIFY 교차다. 즉 이 모델의 "나쁜 성적표"는 상당 부분 모델 잘못이 아니라 **프롬프트가 두 상태를 구분해주지 않은 결과**다. 상태 정의를 보강해 재측정하면 원인 분포 자체가 크게 바뀔 가능성이 있다. 다만 기존 문서가 지적하듯 판정 불가 비중이 너무 커서 "지금 보이는 A/B 비율은 대표성이 약하다"는 점은 감안해야 한다 — 재측정이 먼저다.
2. **exaone3.5:7.8b는 규칙 위반형(A1+A2+P) 비중이 25~27%로 세 모델 중 가장 높아, 프롬프트 규칙을 추가했을 때 직접 반응할 여지가 크다.** 그러나 B1(12~16%)과 B4(16~22%)가 동시에 크다는 게 걸린다. B1을 줄이려 "모르면 보류하라"를 강조하면 B4가 늘고, B4를 줄이려 "있으면 답하라"를 강조하면 B1이 늘 수 있다. 두 방향을 동시에 겨냥하는 대조 예시(같은 유형인데 답이 있는 경우/없는 경우를 나란히 보여주는 few-shot)가 필요하다.
3. **qwen3:1.7b는 세 조건(test2, test3 ON, test3 OFF) 모두에서 B1이 35~45%로 압도적 1위를 지킨다.** 추론을 켜도 꺼도 같은 패턴이라는 건 이 문제가 프롬프트나 추론 방식이 아니라 **모델 용량 자체의 한계**에 가깝다는 신호다. 프롬프트 제어 우선순위에서는 제외하고, 그래도 쓴다면 대조 데이터 학습(SFT)을 검토해야 한다.
